## ★ 真机试玩二维码（2026-10-01 打通并封装；用户长期约定：每次代码更新都出一次）

**一条命令**：`bash tools/wechat-preview.sh [工程目录] [debug|release] [归档目录]`
（默认 `game-4-mahjong` / `release` / `docs/verify/S13/device`；代码没变只想换新码加 `SKIP_BUILD=1`）
它做完：构建 → **验产物真新** → 探活 IDE → `close` → `open` → 等编译 → `preview` → **JPEG 转真 PNG** → **Vision 解码验证** → 写 README。

**这条链路的四个坑（全在脚本里封好了，列在这里是为了出事时知道去哪看）**：
1. ★ **`cli preview` 在 `close`+`open` 之后首次必报 `✖ compile_start` + `{code:10, message:'错误 undefined'}`** ——
   而 `cli open` 明明返回 `✔ open`。真相：**上下文"打开了"≠"能编译"**，内部编译服务还没挂载完。
   ⚠️ **对策是"重试到成功"（5 次 × 15s），不是"等更久"**——实测等 30s 照样失败，隔 15s 重跑立刻成功。
2. **`--qr-output` 写出的其实是 JPEG**（文件名写 `.png` 也没用，`file` 一看便知）→ 必须 `sips -s format png` 转真 PNG。
3. **`--qr-output` 要的是文件路径，且父目录必须是真目录、不能是软链接** → `/tmp/qr.png` 必失败（`/tmp` 是软链），要用 `/private/tmp/...` 或先 `mkdir -p` 一个子目录。
4. **"生成成功" ≠ "能扫"** → 用 **macOS 自带 Vision 框架**解码自检（零依赖，脚本内联了你 Swift 脚本），拿到 `mp.weixin.qq.com/a/~~...~~` 才算数。

**预览码语义**：**有且只有最新一张有效**——重跑一次上一张立刻作废。
→ 归档目录只留当前那张，同目录 `README.md` 写明生成时间 / AppID / 包体字节数 / 解码内容 / 作废规则。
→ 「扫码后现象和最新改动对不上」时，**第一怀疑对象是扫了旧码**。

**预览 vs 上线**：`preview` 出的是「开发版预览」，**不会覆盖线上版本**；只有 `cli upload` 才会在 mp 后台生成体验版。

## game-4 S7 动效系统（2026-09-30 完成，纯表现层改造，玩法数值零改动）
- **新增 `ui/MotionFx.ts`（718 行）= 动效基础设施**：带 tag 的补间注册表（同节点同 tag 先 stop 后起，避免抢 `position`）、六条语义曲线（`EASE_ENTER=quadOut` / `EASE_MOVE=quadOut` / `EASE_POP=backOut` / `EASE_EXIT=quadIn` / `EASE_IDLE=sineInOut` / `EASE_REJECT=sineOut`）、跨容器世界坐标换算（`worldPosOf` / `worldToLocal` / `between`）、特效对象池（碎屑/脉冲/白闪/奖励图标，`_gen` 代次号防重 + `autoRecycle` 到期兜底回收）。

- 🔴 **Cocos Creator 3.8 的 Tween 没有 `bezierTo` / `splineTo`**（2.x Action 系统残留；3.0 重写后只剩 `to/by/set/delay/repeat/call`）。弧线必须自己算：`MotionFx.arc()` 把三次贝塞尔按 `ease(i/n)` 采样成 **8 段直线**，缓动作用在整条弧的参数上、段内用 `linear`（逐段套缓动会"一顿一顿往前拱"）。
- 铁律落点：**状态推进一律 `setTimeout`，禁止 `tween().call()`** —— 补间被 stop / 换父 / 回收后回调永不执行，`_busy` 永久 true 直接死锁。
- **五类时机**：① 开局入场（L1 240ms / L2-4 160ms，按层错峰 + 底部三件套滑入 + 槽格依次点亮）② 点击（touchStart 即压缩 60ms、选中上浮 6px+放大 1.12、**按距离推导飞行时长** `MOVE_SPEED=1.6px/ms`、落位 squash、**被压住的牌给拒绝反馈**）③ 消除（**先聚拢后消除**、前摇停 70ms、再胀 1.20→缩 0、碎屑 6-10 个、槽位余 3 格描边呼吸 4 次）④ 道具奖励（**弧线飞行 + 落点脉冲**，落点按道具有意义地选）⑤ 洗牌（**三段式：收拢 → 数据重排 120ms → 按层铺开**，总长硬约束 ≤800ms，层数变多时压缩步长而非拉长总长）。

- ⚠️ **冒烟测试证明不了"动效真的播了"**：本轮 3 个真实缺陷（① 入场缩放补间与淡入补间共用 tag → 被 `stop` 掉、动画实际没播；② 飞行窗口内取消选中 → 落位定时器不校验归属，同张牌同时在场/在槽；③ 洗牌收尾抢锁）**在冒烟里全是绿灯**，靠第二遍**独立代码审查**才抓到。→ **以后表现层改造必须加一轮"只读 + 不看构建结果"的独立代码审查**。

### 1. ★★ 堆叠模型重写：floor 升为一等公民（本轮最重的改动）

**旧模型的病根（三条叠在一起，必然贴下缘）**：
① 层是**副产品**（先铺满格点、装不下才在**同一批格点**上再摞一层 → 层与层**位置完全重合**）；
② 纵向"谁压谁"由**行号**决定；③ 行的分布**下密上疏**（`WEIGHT_Y = 0.7`）。
→ 结果必然是**贴着下边缘的一坨小土丘**、上方一大片空白（用户截图精确命中"简单地从下往上堆叠"）。

**新模型**：`F = clamp(ceil(count/PER), 1, MAX)` → 按 `DECAY^k` **由下往上递减**分配张数（最大余数法）
→ 每层是**中心独立随机**的"片"（整堆落点 `DRIFT` + 层间错开 `LAYER_DRIFT`）
→ 片内按**切比雪夫距离**加权聚集（`TIGHT`）→ 层间纵向错开 `GAP`（**位移以中间层为基准上下对称**，
只往上/往下挪都会跑偏）。
- **★ 开局可点是物理结果，不是运气**：顶层张数最少 → 顶层片最小 → **盖不住下一层** → 下层从缝里露出来。
- **★ 深度公式唯一口径**（首次铺牌与洗牌重排**共用**，历史上两处各写一遍写错过一次）：
  `depthOfCell(grid, cell) = cell.floor * 100000 + cell.layer * 1000 + (grid.rows - 1 - cell.r)`
- **已删除** `WEIGHT_Y` / `WEIGHT_X`（正是"贴下缘"的成因）。

### 2. ★★ ③ 与 ④ 为什么必须同一次做（易忘的因果）

牌放大 1/4 → 格点从 **6×11=66 掉到 5×8=40**，而 L4 有 96 张 → **"同格叠放"再也补不上缺口**
（40 格摞到 96 张 = 平均每格 2.4 张，会变成均匀方块）。只能靠**分层**消化。
**单独放大不改堆叠模型 → 96 张直接溢出牌堆区。**

### 4. ★ 复活新规则（需求 #2）的三条要点

1. `clearN = ceil(槽容量 × 0.5) = 4`，消**槽内最后 4 张**（数组尾部），保留前 4 张；暂存架不动。

   （`planReshuffle(..., this._slots.map(e => e.key), ...)`）—— 否则会出现
   "牌堆自己是可解的、但玩家槽里已躺着 4 张 → 重排后照样通不了"的空转。
   日志里必须出现「（槽内保留 4 张参与校验）」。

### 5. ★★ 方法论（已同步进 skill `cocos-to-wechat-minigame`，以后照做）

1. **`fill:<n>` —— 用"预判"代替"撞运气"的冒烟动作**。旧 `dirty` **允许撞上「吃」**

   `fill` 把"这一步会不会消"**完整预判**一遍（碰/杠/吃都算，规则必须与 `MatchRule.findMatch` 一致）。

2. **无头探针的 `sync.sh`：别再手工改 import**。手工替换的翻车方式 = 源码里**多 import 一个符号**

### ★ 音效技术路线「借真人干声 + 重写声调」（S12 独创，可复用）
- **吃**：四川 `[tsʰɿ]` = 普通话**「次」cì** 的段音，只差声调 → edge-tts「次」+ `--pitch` 下移，轮廓 RMSE **1.38 半音**。
- **碰**：四川 `[pʰoŋ]`，普通话**无 p+ong** → 借**「捧」pěng**(214，与四川去声 213 同族) + **整段重采样 ×0.82** → 一步同时降共振峰与音高，韵母 /ɤ/→/o/（F2 1079→861Hz）。
- 💡 **重采样等比缩放所有频率 → 音高轮廓的"形状"(半音差)不变**，所以 resample 档要按 **F2** 选，不能按 RMSE 选。
- 🔴 **data URI 里塞裸 PCM 会静默失败**（少 44 字节 RIFF 头 → 页面正常但没声音），必须用 `wave` 模块写完整头；用 CDP `new Audio(dataURI)` 查 `duration` 才能发现。
- 其它坑：`--pitch=-40Hz` 必须等号形式（否则被 argparse 当选项、静默失败）；同屏联动的物理量要由**同一常量**派生（槽位条被裁半个）；"闭嘴"时上下颚会叠成一只眼睛 → `open<4` 不画。

### S12.1 音效加长 + 入槽手感 v2（2026-10-01 傍晚；**仍只出 demo，游戏源码零改动**）

用户第一轮反馈①动效保留②音效要**延长带尾音、更像真人**③入槽**延迟肉眼可见**+**按下放大**+**飞更快**。

- ★★ **「延长」是感知长度，不是时长数字**。三层（全时域、不碰谐波）：
  ① `trim2()` **非对称裁剪**（头 6% 清静音 / **尾只砍 1.2%** 保住真人渐弱 —— 原来 6% 阈值白丢 50ms）；
  ② `steady_tail()`+`sustain()` **周期对齐拖长**；③ `room_tail()` 指数衰减噪声 IR + FFT 卷积 + 1.6ms 低通。
- 🔴 **周期对齐"从哪取周期"决定成败**：必须**同时**满足「还有能量」且「仍是稳态元音」，
  并**吸附到声门脉冲峰值**。只看能量会滑进衰减区 → 复读出来是**机器嗡声**
  （时长数字变长了，实际只有 −62~−68dBFS，等于没声音）。**判据 = 逐 50ms 打 dBFS。**
- 🔴 **在"已被 trim 过的成品"上加长 = 硬接一截**（自然衰减早没了）→ 必须**从 raw 原料重建**。
- **自相关窗长必须随音高自适应**（≥4.5 个周期）：固定 30ms 对 74Hz 男声装不下 3 周期 → r 假性偏低。
- **`contour_of` 必须加能量门 `rms_th=0.18`**：尾部阈值放宽后轻声段 F0 不可靠 → 调值 RMSE **从 1.38 假涨到 22**。
- `seam_check` 是**伪值**（101Hz 与 280Hz 上差 10 倍）→ 废弃，改 `period_corr`（周期自相似）。

### ★ 六条值得复用的经验（都踩过坑）
1. **「消除」不能只消 1 张**：牌是 3 张一组构造的，消 1 张必留 2 张死牌 → 道具亲手制造死局（首次自动化测试就把 L1 卡在 10/12）。改为**消被点牌所在整组 3 张**，守住不变量「每个牌面在局张数 ≡ 0 (mod 3)」。
2. **「先算方案 → 再要权限 → 最后提交」**：洗牌/复活都先在**影子副本**上算可解布局，算不出就**零改动 + 不放行**。不加这步 = 玩家看完 15 秒广告发现牌还是死的。
3. **重排类功能的最小门槛必须随残局放宽**：为满局设计的 `MIN_PICKABLE=6` 在残局 5~8 张时几乎无法满足 → **洗牌静默失败**（表现为"点了没反应"）。改为 `minPick = max(2, min(6, ceil(ids/3)))`。
4. **门禁面板只"转交"不放行**：初版在面板点按钮时就放行了 → 等于**没看广告也能用道具**。真广告/模拟广告/分享必须收敛到同一个 `settle(ok)`。
5. **复活要做对两件事**：① 槽里的牌**退回场上**而非销毁（销毁会永久少牌 → "清空全部牌"永远达不成）；② 退回后**必须重排并保证可解**。按 `id` 精确定位（同名多张时按牌面找回会还原错）。
6. **「先看日志」的验证有盲区**：本轮三个面板排版缺陷（副标题被按钮压住、按钮文案末字被裁、标题与副标题只剩 3px）**全是逻辑正确但视觉错**，只有**截图留痕**才发现。→ 每个里程碑必须截图。

### 冒烟测试新增 `dirty:<n>` 动作（负向测试原语）

### ★★ 两个必须记住的坑
- **"自适应填满容器"的算法，扩容会把新空间吃掉**：`buildGrid` 原为

- **层高的正确测法**：不能用"各层 y 均值之差"（混着行距与同格叠距）；

### ★★★★★ 本轮最值钱的产出：`UIOpacity` 对 Graphics 是「一次性覆写」

> **推翻了本工程流传两轮的错误结论**「`UIOpacity` 对 `Graphics` 不生效」——
> 而那条错结论刚刚炸出一次全屏黑屏。**以后凡是要给 Graphics / 多档图形调透明度，先读这段。**

- 机制：引擎在 `opacity` **变脏的那几帧**，把子树顶点 alpha **整个替换**成级联值
  （`cocos/2d/assembler/utils.ts: updateOpacity` → `vb[i] = (vb[i] & 0x00ffffff) | (alpha << 24)`，
  **是替换而非乘系数**；`batcher-2d.ts: _handleUIRenderer` 里 Graphics 走 COLOR 分支）。
  **tween 一停就不再置脏**；顶点数据一旦被重建（`render-data` 的 chunk recycle / allocate），
  alpha 就**回落成 Graphics 自己烘焙的 `fillColor` 值**。
- 后果分两种：**多档**图形（四层墨晕）→ 回落成各层各自的 alpha → 分层**会回来**；
  **目标非 255 的单档**图形 → 回落成 255 → 更不透明且**永不恢复**。
- **新判据**（已写死进 `UIFactory.ts` 铁律段，取代旧的"看内部有没有多档 alpha"）：
  只有两种情况可以用 `UIOpacity` —— ① 目标值 **0**（引擎里是硬开关，整棵子树跳过渲染）；
  ② 目标值 **255** 且内部单档（回落值恰好等于目标值）。
  **凡目标值是中间值 → 一律 `alphaPainter` 烘焙**（把 alpha 烤进 fillColor / strokeColor）。
- 全工程 **16 处** `UIOpacity` 按新判据复查：只有失败动效的压暗层 **1 处**违规，已修。
- ⚠️ 更隐蔽的一条：**祖先的 `UIOpacity` 一样会抹平后代** —— `PageManager.open()` 给每个页面节点
  挂了 UIOpacity 做 0.22s 转场淡入，在那 220ms 内**整页所有 Graphics 的分层都是被抹平的**。

### 它炸出的 bug（已修；★ 诊断手法务必记住）

- 现象：判负后 520ms 起**整屏 `#22201C`**（正好 = `CFG.COLOR.INK`），四角与中心**完全同值**、
  **纯黑像素占比 0%**，+3.7s 仍全黑，失败面板"已开"却被整个盖住。
- 根因：压暗层（全屏 INK 矩形、`fillColor` alpha=255）用 UIOpacity 淡到 `DIM_ALPHA=0.10`；
  tween 期间每帧被覆写成 25（**看着完全正常 → 上一轮就这样"通过"了肉眼检查**），
  tween 一停（0.27+0.18=0.45s）→ 顶点重建 → 回落 255 → 永久全黑。
- **★ 诊断手法（可复用）**：`UIOpacity` 的 tween **终点值必须用像素采样复验** ——
  采样**四角 + 中心**，看它是否**等于预期色**，而不是只看"像不像"。
  若四角与中心**完全同值**，就排除了"Canvas 清屏黑"，锁定为"某一层不透明"。
  （PIL 只装在 `/usr/bin/python3`；managed python 没有。）
