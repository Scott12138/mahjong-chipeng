### 二、关键实测（归档 `docs/verify/S7.9/开局可点分布/`）

每关 400 次**确定性**种子（`seed=(i+1)*2654435761`，任何人跑结果逐位一致）：

| 关卡 | 平均可点 | ≥6 达标率 | ≥5 达标率 | 门槛 6 兜底率 | 门槛 5 兜底率 |
|---|---|---|---|---|---|
| L2 | 4.02 | 8.5% | 33.0% | 2.9% | ≈0 |
| L3 | 3.83 | 5.3% | 24.5% | 11.3% | ≈0 |
| L4 | 3.75 | **0.8%** | 16.8% | **72.5%** | **0.06%** |

**核心结论：门槛 6 是失效的** —— 多层堆叠的顶层天生窄，「≥6」是罕见事件，
40 次采样**整体作废**，最终仍用「2~5 张可点、且**从未跑过可解性校验**」的兜底局。
（早前 150 次随机种子测得 L4 = 42.7%，与 72.5% 同属「单次 ≥6 率约 1%」下的样本波动，**以 400 样本为准**。）

⚠️ 复现要点（踩过的三个坑）：副本目录 + 相对 import 改 `./X.ts` + **类型名必须走 `import type`** +
副本 `Generator.ts` 末尾补 `export { buildGrid, sampleCells, buildBag, placeTiles }`；
Node 用 `--experimental-transform-types`（内置，不需要 tsc）。

### 三、静音的查证结论（长期事实）

- Cocos 3.8.8 微信端把 `wx.createInnerAudioContext` 包成音频元素替身 → 这条通道**真实生效**。
- 构建产物里 `setInnerAudioOption` 出现 **0 次** → 现状 = 跟随静音键 = **正是用户要的行为**。
- 遗留：`AudioService.setMuted / toggleMuted` 有实现但**全工程无人调用**（界面没有静音开关）。

## 2. ★ 本轮最重要的架构认识

### 2.1 旧堆叠模型的病根（三条叠在一起，必然贴下缘）
1. 层是**副产品**：先铺满格点，装不下才在**同一批格点**上再摞一层 → 层与层**位置完全重合**；
2. 纵向"谁压谁"由**行号**决定（`depth = 行号反序 × 1000`）；
3. 行的分布是**下密上疏**（`WEIGHT_Y = 0.7`）。
→ 三者合起来 = 牌堆必然是一坨**贴着下边缘的小土丘**、上方一大片空白（用户截图精确命中）。

### 2.2 新模型：floor 升为一等公民
`先定层数 F = clamp(ceil(count/PER), 1, MAX)` → 按 `DECAY^k` 由下往上递减分配张数（最大余数法）
→ 每层是一个**中心独立随机**的"片"（整堆落点 `DRIFT` + 层间错开 `LAYER_DRIFT`）
→ 片内按**切比雪夫距离**加权聚集（`TIGHT`）→ 层间纵向错开 `GAP`，**位移以中间层为基准上下对称**。

**★ 开局可点是物理结果，不是运气**：顶层张数最少 → 顶层的片最小 → **盖不住下一层**
→ 下层的牌从缝里露出来。

**★ 深度公式唯一口径**（首次铺牌与洗牌重排共用，历史上两处各写一遍写错过一次）：
`depthOfCell(grid, cell) = cell.floor * 100000 + cell.layer * 1000 + (grid.rows - 1 - cell.r)`

### 2.3 ★★ ③ 与 ④ 为什么必须一起做
牌放大 1/4 → 格点从 **6×11=66 掉到 5×8=40**，而 L4 有 96 张：
**"同格叠放"再也补不上缺口**（40 格摞到 96 张会变成均匀方块）。只能靠**分层**消化。
单独放大不改堆叠模型 → 96 张直接溢出牌堆区。

### 2.4 量化验收（全部通过）
| 项 | 结果 |
|---|---|
| 分词（由下往上） | L2 16/11/9（3层）· L3 21/16/11/9/6（5层）· L4 30/22/16/12/9/7（6层） |
| 开局可点 | L2 5–9 · L3 5–9 · L4 5–8（`MIN_PICKABLE=5` 成立） |
| 越界 | 四关各 20 局，**出区牌 0 张** |
| 认证（40 局） | `DRIFT 0.10` → L4 30/40；**`DRIFT 0.30`（采用）→ 26/40**；两档开局可点中位数都是 7 |
| 生成耗时 | L4 约 88–139ms |
| draw call | L1 61 / L2 92 / L3 140 / **L4 162**（比 S10 的 186 **更低**，分层后重叠牌变少） |

### 2.5 复活新规则的两个要点
- `clearN = ceil(槽容量 × 0.5) = 4`，消**槽内最后 4 张**（数组尾部），保留前 4 张；暂存架不动。
- ★ **重排的可解性校验必须把"槽里保留的那几张"算进去**
  （`planReshuffle(..., this._slots.map(e => e.key), ...)`），
  否则会出现"牌堆自己是可解的、但玩家槽里已躺着 4 张 → 重排后照样通不了"的空转。
- ⚠️ **有意接受的不变量破坏**：原来的"在局张数 ≡ 0 (mod 3)"被打破（消 4 不是 3 的倍数），
  终局会剩 1~2 张消不掉的牌。**收口只需把比例改成 `1/4`(2张) 或 `3/4`(6张)**。
- 按钮文案改成**从参数算**：`` `看广告复活（消 ${reviveClear} 张 + 重排）` ``。

## 3. ★★ 本轮最有价值的方法论（已写进 skill）

### 3.1 `fill:<n>` —— 用"预判"代替"撞运气"的冒烟动作
旧的 `dirty` **允许撞上「吃」**（这正是它能抓「吃」动效的原因）→ 槽内凑出连号就消 →
**槽永远到不了 8 张** → 永远逼不出「槽满判负」。
新增 `fill:<n>`：把"这一步会不会消"**完整预判**一遍（碰/杠/吃都算，规则必须与 `MatchRule.findMatch` 一致），
只点不会引发消除的牌 → **必定**填满槽。
> **推广**：任何"要走到某个极端状态才能触发"的功能，都需要一个**专门构造该状态**的动作，
> 而不是指望随机操作撞上去。

### 3.2 无头探针的 `sync.sh`（别再手工改 import）
手工字符串替换 import 的翻车方式：源码里**多 import 一个符号** → 替换静默失配 →
报 `does not provide an export named 'X'`，**报错指向被 import 的文件**（让人以为数据文件坏了）。
`sync.sh` 的做法：① 扫 `export interface/type` 自动拿类型名单拆 `import type`；
② **路径压平成 `./X.ts`**（探针目录是平铺的，源码里的 `../CFG` 只补后缀会被解析到 /tmp/CFG.ts）；
③ 追加 `export { 内部函数 }`（先扫已有导出，否则 `Duplicate export`）。

### 3.3 ★★ 纯数据怎么"看图"：数据 → SVG → 无头 Chrome 截图
分层几何这种问题读数字太慢。折中：探针直接输出 SVG（每张牌一个 `<rect>`、
**按层上色**、开局可点描橙框、画出牌堆区/槽位条边界），再用已有的无头 Chrome 截 PNG。
- **不需要起游戏**，几何对错一眼看出；
- 支持 **CLI 覆盖参数做 A/B**（`DRIFT=0` vs `0.30` 各一张并排）→
  "为什么选这个值"有了**可复看的证据**（本轮就是靠这两张图定的参数）；
- 机器判（程序算 rect 是否出区）+ 肉眼判（图上看有没有出框）**互为交叉验证**。
