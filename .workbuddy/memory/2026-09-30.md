2. `--build '{"json":...}'` JSON 字符串形式**不被解析**（回落默认 web-desktop）→ 必须用 `configPath=`。
3. **CLI 包装脚本里有 `cd "$CWD"`** → `--project` 传**相对路径**会被解析到错误位置，报的却是 `✖ preparing / openProject 异常`（完全看不出是路径问题）→ 必须转绝对路径。
4. 工具**冷启动要 60 秒以上**，启动后立刻调 `open` 必失败（`✖ IDE may already started at port xxx / wait IDE port timeout`，或 `✖ preparing`）→ 先用 `cli islogin` 轮询探活再 open。
5. bash 里 `echo "$OUT" | grep -q PAT` 配 `set -o pipefail` 会因 grep 提前退出触发 SIGPIPE 被误判失败 → 改用 here-string `grep -q PAT <<<"$OUT"`。

### 关键工程坑（已全部固化进 skill `cocos-to-wechat-minigame`）

1. **无头构建下场景里的自定义组件会被静默丢弃**：asset-db 反序列化场景**早于**脚本类注册 → `Script "xxx" is missing or invalid`，构建却"成功"。解法：场景保持零脚本，由 `Bootstrap.ts` 运行时自挂 `GameRoot`（双路径：`EVENT_AFTER_SCENE_LAUNCH` + 立即执行一次）。
2. 运行时 `new Node()` 默认落在 `DEFAULT` 层，而 2D 相机只渲染 `UI_2D` → 画面全空。必须显式 `node.layer = Layers.Enum.UI_2D`。
3. **状态机解锁绝不要挂在 tween 回调上**：动效链路一旦异常，回调不触发 → 页面永久切不动。改用 `setTimeout(..., 时长+20ms)`。
4. `PageManager.instance` 从"静默返回 null"改成**抛异常**，让漏调 `create()` 这类 bug 立刻暴露（这次就是它隐藏了白屏真因）。
5. **web 模板写死 `#GameDiv{width:1280px;height:960px}`** → 窗口更窄时 canvas 溢出，引擎 `view.getVisibleSize()` 错成 720×540，竖屏布局全偏。验证脚本必须锁 720×1280 视口 + 注入 CSS 撑满，并**自检 `visible === 设计分辨率`**。
6. `Page.addScriptToEvaluateOnNewDocument` 执行时 `document.head` / `documentElement` **都还是 null** → 用 `MutationObserver` 等节点出现再插 `<style>`。

### 体积实测（关键结论）

- wechatgame **release = 2.9MB**（cocos-js 2.5M、assets 仅 **212KB**、web-adapter 88K），红线 4MB，**余量 1.1MB** → **技术栈可行性确认**。
- assets 只有 212KB 是「代码驱动 UI + 矢量画牌面、零贴图」的直接红利。
- 仍可回收的余量：`engine.json` 里 `spine` / `dragon-bones` / `tiled-map` / `video` / `webview` / `physics-2d-box2d` 全用不到（日志里 `[PHYSICS2D]: register box2d.` 就是它在包里的证据）。

## 万子文字「纵向居中」修正（用户验收反馈，只改这一处）

用户反馈：条筒好看，**万子字太偏下**。

### 量化结果（改前）

- 牌体 1.6..174.4、内墨线框 8.5..167.5 —— **两者中心都是 y=88**，这是唯一正确的居中基准。
- 原坐标 `数字 y=86 / 萬 y=158`：像素实测墨迹平均中心 **y=102.4**（偏下 14.4px），
  且**「萬」字底已压出内墨线框**（下留白 **-0.5**，即溢出）；上留白却有 25.5 —— 明显失衡。
- 对照条族 7 条（上下留白各 13.5）、筒族 9 筒（各 8.5）：**同族元素都走"对称留白"**，万子是唯一的例外。

### 改法

`数字 y=72 / 萬 y=144`（整块上移 14px）。改后实测**平均中心 y=88.4（偏差 +0.4px）**，上下留白各约 12.7。
→ 两处设计稿都改了：`guochao-tiles.html` 的 `glyphWan()`、`style-directions.html:294-295` 手抄的那份（**grep 旧值确认无残留**）。

### ⚠️ 量"居中"的坑（差点又算错）

- **SVG `<text>` 的 `getBBox()` 返回 font box（≈1.39em，含行高空白），不是字形墨迹** —— 用它算只会得到 10.2px 的偏移，比真值少 3.7px。
- 正确做法：页面里开 canvas 用 `measureText().actualBoundingBoxAscent/Descent` 拿**墨迹**真值。
  实测 64px 宋体「萬」：getBBox 高 88.7，**墨迹只有 62.8**。
- 中文字面框经验值 **≈ [基线−0.795em, 基线+0.186em]**。
- **「一」这类字墨迹天生偏下，绝不能为它单独挪基线**（一挪其余 8 张全偏上）；判据是**整排平均中心**。
