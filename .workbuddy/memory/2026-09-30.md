- **根因（已用对照组证实）**：
  1. `download.cocos.com/CocosPortal/image/*.png` → **200**（同域名可达）；`download.cocos.com/CocosDashboard/*.dmg|.zip` → **403**。即 CDN 对**安装包目录做了出口 IP／地域限制**，网络本身没问题。
  2. 本机三层出口：沙箱内置透明代理（env `HTTP(S)_PROXY=127.0.0.1:55435`）、macOS 系统代理 `127.0.0.1:7890`（ClashX）、以及 ClashX 可能的 TUN 增强模式 → 连 `curl --noproxy '*'` 也是 403，说明流量仍被接管并走海外出口。
  3. 我最初的错误：没做"同域名对照组"，只反复换版本号（v2.0.0/v1.3.2/v2.2.1）和 UA/Referer 穷举 → 每轮 curl 15~25s 超时叠加，看起来就是"卡住"。
  4. 另一个坑：我试的老版本文件名在 CDN 上**根本不存在**，openresty 对不存在的对象也返回 403（而非 404），误导了判断。

**新增/更新的 5 个坑与解法（全部实测）：**
1. Cocos 构建顶层 `appid=xxx` 会被**静默忽略**（产物仍是模板 demo 号 `wx6ac3f5090a6b99c5`）→ 唯一可靠通道是 `--build "configPath=xxx.json"`，AppID 写在 `packages.wechatgame.appid`。
2. `--build '{"json":...}'` JSON 字符串形式**不被解析**（回落默认 web-desktop）→ 必须用 `configPath=`。
3. **CLI 包装脚本里有 `cd "$CWD"`** → `--project` 传**相对路径**会被解析到错误位置，报的却是 `✖ preparing / openProject 异常`（完全看不出是路径问题）→ 必须转绝对路径。
4. 工具**冷启动要 60 秒以上**，启动后立刻调 `open` 必失败（`✖ IDE may already started at port xxx / wait IDE port timeout`，或 `✖ preparing`）→ 先用 `cli islogin` 轮询探活再 open。
5. bash 里 `echo "$OUT" | grep -q PAT` 配 `set -o pipefail` 会因 grep 提前退出触发 SIGPIPE 被误判失败 → 改用 here-string `grep -q PAT <<<"$OUT"`。
