5. bash 里 `echo "$OUT" | grep -q PAT` 配 `set -o pipefail` 会因 grep 提前退出触发 SIGPIPE 被误判失败 → 改用 here-string `grep -q PAT <<<"$OUT"`。

### 关键工程坑（已全部固化进 skill `cocos-to-wechat-minigame`）

1. **无头构建下场景里的自定义组件会被静默丢弃**：asset-db 反序列化场景**早于**脚本类注册 → `Script "xxx" is missing or invalid`，构建却"成功"。解法：场景保持零脚本，由 `Bootstrap.ts` 运行时自挂 `GameRoot`（双路径：`EVENT_AFTER_SCENE_LAUNCH` + 立即执行一次）。
2. 运行时 `new Node()` 默认落在 `DEFAULT` 层，而 2D 相机只渲染 `UI_2D` → 画面全空。必须显式 `node.layer = Layers.Enum.UI_2D`。
3. **状态机解锁绝不要挂在 tween 回调上**：动效链路一旦异常，回调不触发 → 页面永久切不动。改用 `setTimeout(..., 时长+20ms)`。
4. `PageManager.instance` 从"静默返回 null"改成**抛异常**，让漏调 `create()` 这类 bug 立刻暴露（这次就是它隐藏了白屏真因）。
5. **web 模板写死 `#GameDiv{width:1280px;height:960px}`** → 窗口更窄时 canvas 溢出，引擎 `view.getVisibleSize()` 错成 720×540，竖屏布局全偏。验证脚本必须锁 720×1280 视口 + 注入 CSS 撑满，并**自检 `visible === 设计分辨率`**。
6. `Page.addScriptToEvaluateOnNewDocument` 执行时 `document.head` / `documentElement` **都还是 null** → 用 `MutationObserver` 等节点出现再插 `<style>`。

### 体积实测（关键结论）

- wechatgame **release = 2.9MB**（cocos-js 2.5M、assets 仅 **212KB**、web-adapter 88K），红线 4MB，**余量 1.1MB** → **技术栈可行性确认**。
- assets 只有 212KB 是「代码驱动 UI + 矢量画牌面、零贴图」的直接红利。
- 仍可回收的余量：`engine.json` 里 `spine` / `dragon-bones` / `tiled-map` / `video` / `webview` / `physics-2d-box2d` 全用不到（日志里 `[PHYSICS2D]: register box2d.` 就是它在包里的证据）。

## 万子文字「纵向居中」修正（用户验收反馈，只改这一处）

### 量化结果（改前）

- 牌体 1.6..174.4、内墨线框 8.5..167.5 —— **两者中心都是 y=88**，这是唯一正确的居中基准。

- 对照条族 7 条（上下留白各 13.5）、筒族 9 筒（各 8.5）：**同族元素都走"对称留白"**，万子是唯一的例外。

### 改法

### ⚠️ 量"居中"的坑（差点又算错）

- **SVG `<text>` 的 `getBBox()` 返回 font box（≈1.39em，含行高空白），不是字形墨迹** —— 用它算只会得到 10.2px 的偏移，比真值少 3.7px。
- 正确做法：页面里开 canvas 用 `measureText().actualBoundingBoxAscent/Descent` 拿**墨迹**真值。
  实测 64px 宋体「萬」：getBBox 高 88.7，**墨迹只有 62.8**。
- 中文字面框经验值 **≈ [基线−0.795em, 基线+0.186em]**。
- **「一」这类字墨迹天生偏下，绝不能为它单独挪基线**（一挪其余 8 张全偏上）；判据是**整排平均中心**。

- **`ui/AudioService.ts`**：8 条声道池（不是 `playOneShot`）／`MIN_GAP_MS=45` 节流／
  `FLY_IN_LAND_GAP_MS=130`（24 张牌 1 秒落地不节流会糊成白噪声）／**加载未完成静默跳过不补播**。
- ⚠️ **Cocos 3.8 的 `AudioSource` 没有 `playbackRate`**（2.x 有，3.x 重写音频系统时移除，`cc.d.ts` 逐成员确认）。
  → 连章音高**必须在合成阶段预生成 4 档**（`COMBO_RATES=[1.0,1.122,1.260,1.414]`），运行时选文件而非变速；代价 +18KB。
- ⚠️ **macOS 系统不支持 MP3 编码**（`-f mp4f -d .mp3` → `ExtAudioFileSetProperty ('cfmt') failed ('fmt?')`），只能用 m4a。

## ② 消除动效升级

### 2a「碰」= 三张牌先碰在一起，然后才消除

- 旧版只做"三张各自上浮放大"，三张**彼此没有任何空间关系**。新版三段式：
  蓄力（朝远离中心各退 `CLASH_PULLBACK=12px`，"攒势"）→ **冲刺（`EASE_DASH='quadIn'`，"撞过去"）**
  → 撞击帧（squash `0.84/1.16` + 冲击环 + 碎屑 + 牌堆上踢 + 音 + 震）→ `POP_HOLD=0.06s` 停一拍 → 释放（胀 1.20 → 缩 0）。
- ⚠️ **曲线必须是 `quadIn`**：`quadOut` 冲过去会在到达时减速，看起来像"小心翼翼地靠拢"，完全没有撞击感。
- 撞上后中心间距 = 槽格宽 × **0.45**（碰的三张牌面相同，重叠不丢信息，看到的是"变厚的一张牌"）；
  「吃」的三张牌面不同，用更保守的 0.74。
- **抖"牌堆层"而不是"整屏镜头"**：全屏抖动会改变 `view.getVisibleSize()` 与触摸坐标换算，且一局几十次会生理不适。

### 2b 连章（此前完全不存在，本轮新建）

- 判定用**时间戳窗口**（`_comboAt`）而非"定时器重置" —— 时间戳无状态，不存在"页面切走忘清理"的残留。
- `COMBO_WINDOW=3.6s`：按实际节奏倒推（点牌→选中 180→飞行 ≤300→落位 90→聚拢 90→撞击+释放 590 ≈ 2.6~3.0s）。
  **初版 2.4s 踩坑**：跑完整关一次连章都没出现（窗口小于真人连打的实际间隔）。连锁消除间隔≈0，必然触发。
- **"丝滑"= 长时长 + 首尾速度为零的曲线 + 无抖动无闪烁** → 全程 `sineInOut`，流光带 0.46s / 文字 0.92s，
  与「碰」的 0.2s 硬冲击形成 **爆发 vs 流动**，靠时间尺度分层共存。
- 三要素：流光带横扫槽位条 + 「连章 ×N」上浮 + **音调阶梯（4 档）**。
- **飘字与连章二选一**：连章信息量已覆盖牌型，再叠 96px「碰」字会互相削弱。
- 实测：`消除节奏 距上次 3533ms → 层数 2（窗口 3600ms）` + `连章 ×2`，同一局还通关 12/12。

## ③ 入场逐张飞入

- 起点 = 目标**正上方 680px** + 横向随机 ±96 + 角度随机 ±24°；`backOut` 过冲落位 + 落位挤压 + 落牌声。
- **按深度升序**（底层先落），否则"上面的牌已就位、下面的还在飞"的穿模。
- `FLY_IN_TOTAL_MAX=1.05s`：牌多时压缩错峰步长，不把入场拉长到 2 秒。
- 两个"看起来像 bug"的坑：① **起始态必须在 `buildStack()` 里摆好**（等 `onEnter` 会"先在正确位置闪一帧再集体跳上天"），
  且 `playEnterMotion()` **复用**该起点、不重随机（重随机会让起点跳变）；② **兜底复位必须复位 `position`**（只复位 scale/opacity 会让那张牌永久停在屏幕外）。

## ④ 震动

- **稀缺资源，只用三档**：`light`（按下）/ `medium`（碰消除、复活）/ `heavy`（失败）。
  连消 / 洗牌 / 加槽**一律不震**；误操作（`rejectBlocked`）**有声音但不震** —— 震动是"你做对了"的正向信号。
- `MIN_GAP_MS=60`：线性马达起振/收尾没完就再来一次会糊成"一次更弱的震"。
- `navigator.vibrate` 兜底；`wx.vibrateShort({type})` 必须给 `fail` 回调（老基础库会走 fail）。

## ⑤ 本轮修掉的两个真实缺陷

| 缺陷 | 根因 |
|---|---|
| **不限时关卡判负原因恒显示「时间到」** | 结算页用 `_timeLeft <= 0 ? '时间到' : '槽位满了'` 反推，而**不限时关卡 `_timeLeft` 恒为 0**。→ 改为由判负入口写 `_failReason`（`slotfull`/`timeout`） |
| **引擎性能面板盖住整条槽位条** | web 模板把 `showFPS` **写死 true**，面板固定画左下角，而 `SLOT_BAR_Y=-424` 正在那片区域 → 消除动效全被遮住。→ 新增 `CFG.DEBUG.STATS`（默认 false）+ `Bootstrap.applyStats()`；⚠️ `profiler.hideStats()` 在 `director.root` 就绪前会抛异常，**异常会中断整个模块 → GameRoot 不挂载 → 游戏白屏**，所以必须 try/catch + 延时重试 |

## ⑥ ⚠️ 测试环境陷阱（最有价值的一条）

**无头 Chrome 会把后台/被遮挡窗口的 `setTimeout` 节流到 1 秒。**
本工程铁律是"状态流转只走 setTimeout"，于是落位/解锁/结算定时器全被拉长到 ~1000ms。
表现极具误导性：设计上「拿牌 → 441ms 后落位」实际 1000ms，自动化每 800ms 点一次就撞进飞行窗口 →
被 B7 判成"点错了、撤回"，日志里只剩 `拿牌 → 取消选中 → 拿牌 → 落位 → 落位放弃` 的循环，**看起来像游戏有 bug**。
→ `tools/web-smoke.mjs` 必须加 `--disable-background-timer-throttling --disable-backgrounding-occluded-windows
--disable-renderer-backgrounding`。修好后同用例 `落位放弃: 0 / 取消选中: 0`。

排查时新增的两条面包屑（值得长期保留）：`拿牌 id=… 选中 180ms + 飞行 300ms → 落位倒计时 500ms`
与 `落位放弃 id=…：<原因>` —— **拿牌到落位的时长一旦超过玩家两次点击的间隔，就会退化成
"点一下、撤回一下"的死循环，而现象完全看不出是时长问题**。

## ⑦ 新增的三个工具

| 工具 | 作用 |
|---|---|
| `tools/smoke-run.sh` | 一条命令跑完「起服务器 → 冒烟 → 收服务器」。**必须封装**：Bash 工具的后台进程在调用结束就被回收，分两步做会得到误导性的 `HTTP 502` / `canvas: null` |
