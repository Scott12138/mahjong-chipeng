## 五、迭代过程与判定

### 5.1 背景底图（3 轮，第 3 轮通过）

| 轮次 | 内容 | 判定 |
|---|---|---|
| R1 | 宣纸底 + 页框 + 角花 + 中央立牌 + 承托台 | ⚠️ 接近：中部有横贯色带、承托台是金黄色、牌体太圆像枕头 |
| R2 | 修掉色带与金黄台 | ✅ 背景干净了，但**中央那张 3D 牌会与引擎自己画的大牌重叠** → 形态不可用 |
| R3 | 去掉一切主体物，只留「纸底 + 页框 + 角花」 | ✅ **通过** —— 这正是「位图背景 + 引擎叠字」唯一不会出错的形态 |

> **为什么最终首页没有用 R3，而是用 R4**：R4 本身就是一张**同体系的成品**（也是宣纸底 + 朱红双线页框），
> 但它额外带了专业级 3D 渲染的标题与三张立体牌。用户指定首页直接用它。

### 5.2 首页按钮擦除（1 件 P 图工作，踩了 3 个坑）

用 PIL 把 R4 图内「开始游戏」按钮擦成纯纸底，给引擎的动态按钮腾位。

| 现象 | 真实原因 | 解法 |
|---|---|---|
| 第 1 次：**把三张牌横切了一刀**，按钮却完好 | y 检测上限设成 1010，而按钮实际从 y≈1045 才开始；命中的红色其实来自**牌上的「萬」字与筒饼红圈** | 把检测区间收窄到「说明行之下、提示行之上」，并加**包围盒形态自检**（宽 > 半屏、高宽比 0.10~0.45，否则报错退出） |
| 第 2 次：擦除区浮出**红色角花碎片** | `is_paperlike` 用**整行均值**判「干净纸底」，而居中排版的文字行里文字只占一段，均值仍接近纸色 → **提示行文字被当成干净底卷进了纹理源** | 改用**暗部 8% 分位数**判据（`np.percentile(pixels, 8)`），文字行动辄掉到 60 以下，一票否决 |
| 第 3 次：擦除区出现**等间距竖条纹** | 纹理源只有 98px 宽，横向平铺 7 次留下 7 条硬接缝 | 改用**拉伸**（BILINEAR）而非平铺；并以低权重（0.22）混入，接缝消失 |

**最终擦除质量**：三张牌 / 说明行 / 提示行 / 版本号 / 方印**全部完好**，擦除区只剩极淡纹理过渡，且会被引擎按钮覆盖。
上下锚点行色值 (231,219,201) 与 (230,216,196) 差 1%，插值基底几乎无渐变。

用户两条指令：

> 2、对于**麻将牌的分布，不能影响原来玩法逻辑**，只做其他部分的排版即可」

### 1. 「?」→「规则」：必须放弃「绝对居中」

| | 旧 | 新 |
|---|---|---|
| 形态 | 42×42 **正圆** | **92×46 圆角方**（圆角 15，与底部「重玩」同形制） |
| 文案 / 字号 | `?` / 22 | `规则` / **28** |
| 定位 | 绝对居中 x = 360 | **弹性三段**：关卡名（左）— 规则钮（**紧跟 24px**）— 计时（右对齐） |
| 顶条 | 44 高，中心 +500 | **46** 高，中心 **+499** |

**为什么两个字不能居中**：居中展开占 316~404，而关卡名（宋体 30 + 3px 描边）右边界实测 **321** —— 只剩 9px，必撞。

**实测**（`顶部条-规则钮校验.png`，2.2× 放大 + 三段包围盒）：

```
关卡名 85~321        规则钮 381~478（宽 98）        计时 537~639
        └─ 60px ─┘              └─ 59px ─┘
```

两侧间隙 **60 / 59** —— 弹性布局必然均分余量，**结构性不重叠**（关卡名再长只压缩间隙）。
纵向：规则钮上沿 118、距朱红内框上边线（96）**24px**。

### 2. 牌堆：按用户指令**零改动**

列中心 −210/−70/+70/+210、行中心 +269/+86/−97、牌 123×169、列距 140、行距 183 —— 本轮未触碰。
