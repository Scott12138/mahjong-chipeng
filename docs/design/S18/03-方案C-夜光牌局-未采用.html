麻麻大消除 · 界面改版提案 · 方案 C / 共三案

夜光牌局 —— 霓虹描边 / 扫描线 / 像素爆散 / 高对比

这是三个方案里最跳、最适合短视频截屏传播的一个：深底、霓虹描边、扫描线、像素方块爆散， 缩略图在微信游戏列表里几乎不可能被忽略。它也是离现有国潮体系最远的一个 —— 下面第四节会把这条 trade-off 逐条摊开，不做美化。
全部效果只用「纯色块叠加 + 描边」实现：零贴图、零渐变、零模糊、零阴影， 只用 roundRect / circle / 折线 / 多边形填充 / Label，与工程现有绘制路线一致。

当前首页实况：29 draw call（docs/verify/S10） 重负载参照：L4 峰值 162 DC（S11） 包体：2.15 MB / 4 MB，本方案新增贴图 0 KB 成本等级：高 改动面：改 5 个文件 + 新增 2 个 + 摘掉 1 条路由
先把最大的一条 trade-off 摆在最前面（不美化）： 夜蓝底 + 霓虹青，和已定稿的 27 张真牌牌面（宣纸底 #FBF6EA + 墨线 + 深蓝/朱红/竹绿） 是两套互相冲突的色彩语义：牌面是「印刷在纸上的图案」（暖、低饱和、哑）， 夜景是「屏幕自己发的光」（冷、高饱和、亮）。放在一起必须做三处针对性改造才能共存 （第 ①、④ 节各说一半），不改就是明显不搭。 我不建议直接拿它当整局的主视觉，替代落地方式写在 ④-5。 如果你要的是三个都能稳妥使用的方案，这一份不是 —— 它是一张高赔率高风险的彩票。

选关页删掉之后：继续 / 重玩 / 清空，各走哪条路

主张一句话：把「选关页」压成首页上的一条 4 段霓虹管，刻度即关卡；清空进度不设按钮，藏在刻度管上长按 1.5 秒。
要办的事入口规则 / 状态
从哪继续 唯一主按钮 START_BTN
（396×132，y=−292）		 文案与状态由 SaveService 现算，三种态（首页只有这一个「开始」入口）：
· 0 关通关 → 「开 始 · 第 1 关」
· 有进度未全通 → 「继 续 · 第 N 关」，N = 最小的未通关关号（= 现在 isUnlocked() 的边界）
· 4 关全通 → 「再 来 一 次 · 第 1 关」，并在 y=−350 加一行 20px 小字「4 关已全部通关 · 最快 04:31」
不需要新增存档字段 —— cleared[] 与 isUnlocked()（SaveService.ts:147）已经够用。
重玩某一关 点霓虹管刻度条第 N 段
（y=−138）		 4 段 = 4 关，刻度条自己就是选关器，不再需要独立页面。三种段态：
· 已通关段 → 青色实心（填充 α0.9）+ 青 2 层描边 → 点击进该关重玩
· 当前段 → 品红 3 层描边 + 内部一个 2 秒周期呼吸的方点（α 0.5 ↔ 1.0）→ 点击进该关
· 未解锁段 → 只留 α0.22 的青描边空槽 → 点击后整段横抖 3 帧（±6px / 40ms）+ toast「先通关第 N−1 关」
热区必须吃掉 12px 段缝：每段热区取 135 × 64（123+6×2 × 40+12×2）。 实体高 40px 达不到 44px 最小触摸目标，只能靠热区补；且热区之间不能留缝，否则缝里的点击会丢。
清空进度 长按刻度管整条 1.5 秒
（热区 528×64，y=−138）		 为什么不给独立按钮：这是不可逆的破坏性操作，不该有一个「看得见、点得到」的常驻入口； 而玩家要清的就是这条进度，挂在进度条自己身上语义最自洽，长按 1.5s 又天然防误触。
过程反馈（不做无声长按）：
· 0 ms：4 段描边从青渐变为品红（200 ms）；刻度管下方 12px（y=−166）出现一条 0→528 的填充条（高 4，品红），按长按时长线性生长
· 中途抬手：填充条 120 ms 缩回 0、描边 160 ms 回青，不执行清空
· 到 1500 ms：整条闪 3 次（每 60 ms 一次，α 1.0 ↔ 0.3）→ 4 段变空槽 → SaveService.reset()（SaveService.ts:212 已有）+ 一次 Haptics + toast「进度已清空，回到第 1 关」→ 主按钮文案同帧重算为「开 始 · 第 1 关」
· 不做二次确认弹窗：长按 1.5s 本身已经是确认动作；再加弹窗会让「想清空的人点两次、不想清空的人被挡一次」。
参考图1 的骨架借了什么、弃了什么（逐条对账）：
借：① 顶部一条状态行；② 中央一个大主视觉（它的吉祥物 → 我们的牌塔）；③ 底部一枚大主按钮； ④ 主按钮两侧各一枚功能小钮（它左右各 3 个，我们各 1 个）。 弃：木纹屏风底、大红 + 金、光晕渐变（我们做不了也没必要）、 以及它那些棋牌语义文案（「宗师挑战」「2 连胜」「排行榜」—— 词和概念一个都没抄）。 改动理由：参考图1 是长线运营的棋牌 App，两侧各 3 个入口是内容量撑出来的； 我们是 4 关小游戏，硬凑六个入口只会显得空，所以两侧各留一枚（玩法 / 音效）。
顺手修掉的一处语义风险：现有首页副标题与底部提示写的是「凑齐「碰 / 吃 / 杠」」—— 这三个字是麻将专有动作词，属于「零棋牌语义」红线的擦边球 （README.md §7 记的是「不出现胡牌 / 番数 / 筹码 / 对战」，碰吃杠没写进去，但性质同类）。 方案 C 首页换成中性说法：副标题 「点牌 · 进槽 · 凑三张」、底部 「点牌 → 进槽 → 凑三张」。 这条与风格无关，三个方案都建议改。

顺手查出来的一处「既有」无障碍缺陷（不是本方案引入的）：
现有 COLOR.INK_SOFT #8E8571 对宣纸底 #F2EADA 的对比度只有 3.06 : 1，而它被用在 SIZE_SMALL 22 / SIZE_TINY 20 的小字上 （版本号、三族说明、游戏页的「已清 N/M」行）。按 WCAG AA，小字需要 4.5 : 1 —— 这一批字当前是不合规的。本方案把它换成 #7E8AB8，实测 5.14 : 1。 这条与选哪个方案无关，建议 A / B / C 三案都采用。 （对照：现有 #57503F 对宣纸底 6.69:1 是合规的，问题只在 INK_SOFT 这一档。）
为什么暗底方案对文字对比度的要求应该更严、而不是更松： 暗底会让瞳孔放大、小字的主观可读性确实更差。如果沿用与浅底同一档的 3.06:1， 20px 的刻度提示在夜蓝底上会直接糊掉。所以本方案不但没有放宽，反而把弱化档从 3.06 提到了 5.14。
必须点名的一个「假降饱和」：失败动效里的「全局降饱和」用的是盖一层 #2A3060 α0.43 的冷灰罩。它能看起来把画面压灰， 但它是「加一层冷灰」，不是真的把已有的颜色去饱和：牌面上本来很纯的朱红 #B02A1E 被叠灰后接近于「暗红 + 灰」，而不是「灰红」。在纯色块 + 无 shader 的前提下做不到真 desaturate， 这个近似必须如实标注，不能当作真降饱和验收。

为什么「从中间向两端」而不是从一端扫过去 —— 三条理由：
① 构图对称：牌堆在屏幕上是居中对称的（落点区 x 从 −294 到 +294）。点亮顺序与构图的对称轴一致， 读起来才是「通电 / 开机」；从一端扫过，在竖屏上会被读成「进度条在加载」—— 那是加载感，不是开机感。
② 与下一拍正交：接下来是「牌从下方涌出」（方向 = 下→上）。若点亮也是单向线性（比如左→右）， 两拍都是「扫过去」，节奏会打架；从中间向两端是向外扩张，与随后向上生长正交，两拍不抢。
③ 「点亮完成」落在视线自然落点上：从中间向两端时，最后一格亮起在屏幕两侧边缘 —— 中心构图下那是视线自然扫到的位置，收尾更"完成"；从一端扫过时收尾发生在对角，视线要跳一下。
与现有「牌从下方涌现」的关系：取代，不是叠加在它之前。
现状（CFG.MOTION.SPROUT_*，S17 方案 B）：起点在目标正下方 1.2 个牌高、起始缩放 0.45、 单张升程 0.52 s、总预算 SPROUT_TOTAL_MAX = 1.6 s。
新版把「涌现」降级成开场动画的第 F4 格，并整体压缩：单张 0.52 → 0.34 s、总预算 1.6 → 1.05 s。 两个定义"生长感"的核心参数不动：起点倍数 1.2 与起始缩放 0.45。

为什么不叠加：叠加 = 1.6 + 2.35 = 3.95 s / 关，4 关就是 16 秒纯等待； 而且第 2 次玩同一关时，3.95 s 会让人直接想退出。
两版时长：
· 长版 2350 ms —— 只在「这一关第一次玩」（!SaveService.isCleared(levelId)）时播满 6 格。
· 短版 950 ms —— 重玩已通关的关：跳过 F2 / F3（骨架点亮与扫描线），直接 F4 涌现 + F5 点亮（各压缩 30%）。
· 可跳过：长版期间点击屏幕任意处 → 立刻跳到 F4 起点（不打断，只是把前 1.33 s 折掉）。 2.35 s 只是勉强压在"不可跳过"的门槛内，仍然要给跳过。

① 光敏性：WCAG 2.3.1 禁止「每秒 3 次以上的全屏亮度跳变」。α=1.0 的全屏纯白闪， 对暗环境下的眼睛是生理级刺激，而这个游戏的主力使用时段恰恰是睡前。
② 夜蓝底的放大效应：底越暗，同一 α 的闪白越刺眼 —— 夜蓝 #12173A 与纯白的对比是 17.36 : 1，闪白在这个底上比在宣纸底上"重"得多，不能沿用浅底方案的闪白强度。
③ 更推荐的替代（图 W2 画的就是这一版）：把「闪白」换成「环形冲击波 + 中心保留」 —— 全屏只白到 α 0.35，但中心 r<190 的区域不参与闪白（牌塔所在的那个圆保持原样）。 爆发感来自"外围被白光吃掉"，而不是"整屏被闪一下"，既保住传播力又不刺眼。
若你想要更强的白闪：请让我把它做成默认关闭的设置项，而不是默认开着。

「撕裂」在纯色块下怎么做出来 —— 以及它不是真撕裂，我必须说清楚：
真撕裂（tearing）是把画面本身按水平条带切开、每条独立平移。工程里做不到，因为 UI 是整棵节点树： 你只能移动整个节点，没有"只移动这个节点的一部分"这种操作； 而"把每个节点按条带复制成 6 份、各自裁切"等于把界面 draw call × 6，不可能。
所以我做的是一层「伪撕裂」= 覆盖在画面上的故障条带（glitch bars）： 一叠半透明的纯色横条，每帧换位置和横向错位。观众读到的仍然是"信号断了"， 但底下的画面其实一直在正常渲染，一条都没被切开。 评审时必须按「伪」来接受，不能当成真撕裂验收。
为什么撕裂只跳 3 帧、为什么抖动要用「帧」而不是「秒」： 每帧 50 ms（= 20 Hz）× 3 帧 = 150 ms，频率落在「可读作故障」而不是「可读作频闪」的区间。 如果把条带跳变做到 6 帧以上、或把间隔压到 30 ms（33 Hz），它就从"故障"变成"频闪"， 既触发光敏风险，又会让人觉得"游戏卡死了"。同理，通关的震动锁死在 8 帧 × 22 ms = 176 ms、单帧位移 ≤ 9 px：再长就是"晃"不是"震"，单帧位移再大就有前庭不适的投诉面。
这三组动效都必须挂在同一个「减弱动效」开关下面（见 ④-6）。
失败文案：不说"失败"。用「卡 住 了」+ 按钮「重 来」。 理由：第 1 关被设计成"不可能失败"，失败集中在 L3/L4，而失败原因是"没解了"而不是"你菜"。 「卡住了」把责任放在局面而不是玩家身上；配合"垂落"而不是"弹出"的动效，情绪是"有点可惜"，不是"你输了"。 这是唯一一处我建议改文案的地方，与风格无关，A / B / C 都适用。

4-4　与已有牌面的协调性（诚实回答第一个问题）

问：这套视觉与已有的 27 张真牌牌面（深蓝 / 朱红 / 竹绿，纸底黑线）放在一起协调吗？
答：不协调。而且我能指出具体是哪里不协调、怎么改才能共存。
  • 冲突的本质不是"颜色不一样"，是两套物性语义。 真牌是「印刷在纸上的图案」：暖（纸底 #FBF6EA）、低饱和、哑光、有墨线边界； 夜蓝底是「屏幕自己发的光」：冷、高饱和、光会溢出。把"哑物"放进"光环境"，冲突点有三个，全是具体的：
  • 冲突 1 —— 牌的投影会失效。牌的立体投影是 #22201C × 3 层 × α52 （CFG.TILE.SOLID.SHADOW_*），它靠"比底色暗"成立：对宣纸底 #F2EADA 的对比是 13.6 : 1；对夜蓝底 #12173A 只有 1.06 : 1 —— 几乎完全看不见。结果是牌会"浮"起来，失去"被放在桌面上"的重量感。
    改法：暗底模式不用"更淡的墨"，改用"更黑"（#000000，α 52 → 90）， 并给牌加一圈 1.5px 的 #35E1D0 α0.5 环境光描边，把牌"焊"进夜色（本稿首页画的就是这一版）。
  • 冲突 2 —— 牌的侧壁变成画面里唯一的暖色大块。侧壁 SIDE #E1D5B9 与牌面 #FBF6EA 本来同族（暖米色系，差 12 级明度），在宣纸底上它是"厚度"；在夜蓝底上它是画面中面积最大的暖色， 会与霓虹青形成冷暖对撞，而不是层次。
    改法：暗底模式把侧壁换成 #2E3568（冷灰蓝），读作"被夜光染过的暗边"，不再与霓虹抢色。
  • 冲突 3 —— 12 处朱红角花会把棋牌配色重新拉回来。三张展示牌各 4 段朱红角花（#C4362B）， 在宣纸底上是"器物感"；在夜蓝底上它会变成 12 个暖红亮点，而且朱红与霓虹青是互补关系，会互相"跳"。 更麻烦的是：本方案好不容易才把「朱红 + 墨 + 金」从界面撤出去，这 12 个点又把朱红带回来了。
    改法：给 TileRenderer.drawFrame(g, isDim, k) 增加一个独立的 noCorner 参数 （现在这个开关和"被压住"绑在一起，见 TileRenderer.ts:380 的 if (!isDim)）， 首页展示牌传 true。约 3 行改动。
  • 结论：做完上面三处改造（合计约 12 行代码：侧壁色 + 投影色 + 一个开关）， 牌与夜蓝底能"共存"，但不会"相得益彰" —— 牌仍然像是"被搬进了一个不属于它的房间"。 这三个改造一处都不能省，少了任何一处都会立刻看出不搭。我不会说"毫无违和"。
  • 一句话：牌面在这套视觉里唯一的角色是"夜空里发亮的那三张" —— 它们靠明度（16.10 : 1）而不是靠色彩和谐取胜。接受这一点，方案才成立。

4-5　品类契合度（诚实回答第二个问题）

问：这页的观感与「休闲益智 + 中国风麻将」这个品类定位是否匹配？如果不匹配，你认为它适合什么场景？
答：不匹配。而且我认为它真正有价值的不是"首页长这样"，而是"通关那一下可以这样"。
  • 为什么不匹配：两套联想的交集几乎是空集。 「休闲益智 + 中国风麻将」在用户心里唤起的是可拿在手里把玩的材质：纸、木、竹、瓷 —— 明亮、温润、有触感。 霓虹 / 夜蓝 / 扫描线唤起的是赛博、街机、电子乐、深夜。这两组联想没有交叠。具体后果三条：
  • 后果 1 —— 缩略图会"读成另一个品类"。微信小游戏列表页是浅色底，一张暗底霓虹图在里面会显得"像另一个游戏"。 这既是优势（够跳）也是风险（错位）：用户点进来发现玩法是温和的消除，会有轻微的期待落差。
  • 后果 2 —— 与主力用户群的接受度错配。麻将题材里中老年占比明显更高。 荧光色在他们的审美里普遍被读作"廉价游戏"，而暗底 + 高饱和青对老花眼的负担也确实更大 （本方案弱化文字对比度 5.14 : 1 是达标的，但暗底让小字主观上更吃力这件事，达标也解决不了）。
  • 后果 3 —— 与「零棋牌语义」的关系是双刃的。 好消息：霓虹 / 夜光和中国风棋牌没有任何经典配色关联，从合规角度它比现有的「朱红 + 墨 + 金」安全得多， 这正好是用户说的"色调要变"想要的效果。 坏消息：牌面那三色（深蓝 / 朱红 / 竹绿）和 12 处朱红角花没有变 —— 改配色只改了界面壳，没改牌。而真正的棋牌联想风险在牌上，牌又是已定稿资产。 所以"换色调"这件事，本方案只做到了一半。
  • 我建议的落地方式（最想强调的一条）—— 只把通关动效做成夜光版，页面骨架不要：
    保留 A / B 方案的浅色页面，只在通关那 1.2 秒里把背景短暂压暗成夜蓝 （0.22 s 内盖一层 #12173A α0.92），然后在夜色里做霓虹爆点 + 像素方块 —— 这个做法叫「熄灯爆点」（light-off burst）。四个好处：
    ① 首页与游戏页的品类定位一个字不动；
    ② 短视频最有传播力的那 1.2 秒拿到了（"暗下来 → 炸开"的对比本身就是最好的钩子）；
    ③ 成本极低：只在通关时多 2 个全屏色块的补间 + 一个已有的粒子层；
    ④ 不把"整局都在暗底上玩"的用眼负担加给玩家。
    ③ 里的图 W2/W3/W4 画的就是这个版本 —— 那一刻背景其实还是浅色的，只是被一层夜蓝盖住了 1.2 秒。 这就是本方案真正的用法：它是一段动效，不是一个主题。

4-6　无障碍与合规风险

风险判断与上限
全屏闪白 上限：单帧 16 ms、α ≤ 0.35、单次、间隔 ≥ 5 s。WCAG 2.3.1 禁止 >3 Hz 的全屏亮度跳变； 夜蓝底与纯白对比 17.36 : 1，同一 α 在暗底上的刺激远大于浅底，不能沿用浅底方案的强度。 更推荐「环形冲击波 + 中心保留」（中心 r<190 不参与闪白）。若用户要更强 → 做成默认关闭的设置项。
光敏 / 频闪 撕裂只跳 3 帧 × 50 ms = 150 ms（20 Hz），不做 6 帧以上、间隔不做 <30 ms。 20 Hz × 3 帧整体读作"故障"，33 Hz 会读作"频闪"。这是本方案唯一一处「故意做得不够狠」的地方。
运动刺激 震动锁在 8 帧 × 22 ms、单帧位移 ≤ 9 px；失败抖 4 帧 × 40 ms、单帧 ±4 px。 必须提供「减弱动效」开关 —— 微信小游戏没有系统的 prefers-reduced-motion，只能自己做。 建议把右下角那枚小钮改成「设置」，里面放「音效 / 动效」两个开关（本稿画的是音效，可扩成设置）。
高饱和大色块 霓虹青对夜蓝 10.61 : 1，可读性很好；但大面积高饱和青 + 暗底长时间注视会产生余像。 规则：霓虹只出现在"线"上（描边，宽度 ≤ 16px），不做大面积霓虹填充。 本稿唯一的大面积青是主按钮面（396×132）—— 那是按钮，局部的、可移开视线的。
触摸目标 刻度段实体高只有 40px，低于 44px 最小值 → 热区必须补到 135 × 64，且段缝要分给热区 （缝里也必须能点到）。主按钮 396×132 ✅、小钮 72×72 ✅、刻度段 135×64 ✅（靠热区达标）。
暗底在强光下 户外强光下，暗底 + 霓虹的可读性低于浅底。这是所有暗色界面的通病，设计上无法解决， 只能靠"入场时默认不暗"来规避 —— 这也正是 4-5 建议「只把通关做成夜光」的又一条理由。
合规（棋牌语义） 界面层：本方案在这一点上优于现行方案（朱红 / 金 / 角花从界面退场，不出现任何棋牌语义词）。 牌面层：风险原封不动（三色 + 朱红角花），牌是定稿资产，本方案不碰。 → 提审前仍须按 minigame-publish-compliance 复核一遍（README.md §7 的未解除风险）。

我的结论

方案 C 是一张彩票，不是一份方案。 它在三个方向里画面冲击力最强（深底 + 霓虹在微信列表的浅色底里几乎不会不被看见）， 在合规角度也最有价值（终于把「朱红 + 墨 + 金」从界面上撤干净了，这是现行国潮方案尚未解除的风险）， 但它同时是离现有视觉体系最远的、与品类定位错位最明显的、性能账最难算的一个。 请把它当成"要不要为了那 1.2 秒的爆点付这笔代价"的判断题，而不是"哪个更好看"的选择题。

三个我认为必须一起拍板的事（都不属于风格范畴，建议 A / B / C 三案统一）：

  1. 弱化文字色 INK_SOFT #8E8571 要换：它对宣纸底只有 3.06 : 1， 用在 20–22px 小字上不合 WCAG AA（需 4.5）。本方案给的值 #7E8AB8 是给暗底用的， 浅底方案需要另配一个同族深色（例如把 INK_SOFT 压到 #6F6759 一带再复测）。
  2. 首页文案里的「碰 / 吃 / 杠」要拿掉：这三个是麻将专有动作词， 与「零棋牌语义」是同性质的风险（README.md §7 只是没把它写进例子）。 建议换成「点牌 · 进槽 · 凑三张」。
  3. 通关 / 失败的动效上限要写进规范，而不是留在代码里： 闪白 α ≤ 0.35 且单次、抖动 ≤ 8 帧、撕裂 ≤ 3 帧、粒子 ≤ 40。 再加一个「减弱动效」开关（微信小游戏拿不到系统的 reduced-motion，只能自己做）。 这条不是方案 C 专属 —— 三案都会加通关动效，谁做谁要守。

如果只让我留一句话给这个方案：

把「夜光牌局」当作一段 1.2 秒的动效用，而不是当作一套主题。 页面还是浅色的（A 或 B 都行），只在通关时熄灯：0.22 秒压暗成夜蓝 → 霓虹环形冲击波 → 像素方块爆散 → 亮回来。 这样你拿到了全部传播价值（"暗下来又炸开"是短视频最好的钩子）， 却没有把"整局在暗底上玩"的代价转嫁给玩家，也不用动牌面、不用动路由、不用赌那次未验证的合批行为。 而首页做成夜光深底，我认为是一次不该做的赌博。

最后一句实话：如果三份提案里必须选一份当主视觉，我不推荐这一份 —— 推荐理由在别处（A 或 B 的浅色骨架更贴品类）。但如果你（或用户）就是想要那个"跳"， 请至少接受下面两条不可谈判的前提： ① 闪白上限 α 0.35 且单次；② 必须做「减弱动效」开关。 这两条不是设计偏好，是产品责任。
