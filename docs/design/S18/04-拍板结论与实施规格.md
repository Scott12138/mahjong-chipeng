## 二、两处我按你的决议做了"修正执行"，需要你知道

### 修正 ①：开场与涌现的**分工**（决议 2）

方案 A 原稿的作者建议"**取代**"（把涌现收进开裂那一拍，理由是总时长会到 2.5s+）。
你拍的是"**先开场，再涌现**"—— 我按你的来，但把两段的**内容边界**切开，避免同一件事讲两遍：

| | 负责什么 | 出现的东西 | 时长 |
|---|---|---|---|
| **开场**（IntroAnim） | **舞台** | 页框 / 顶部信息 / 槽位条 / 道具栏（＝全部静态 HUD）淡入，**牌堆区是空的** | 1500 ms |
| **涌现**（S17 的 SPROUT） | **演员** | 牌堆从棋盘里成束升起、挤压、回弹 | 1600 ms |

**关键执行细节（原稿没有的）**：开场第 ⑥ 帧"墨圆裂开"时，**只让 HUD 淡入，不让牌出现**。
原稿那句"棋盘容器 α 0→255"里的"容器"要拆成两个节点 —— HUD 组（裂开时亮）＋ 牌堆组（涌现时才亮）。

**时长**：串行后总等待 **3.1s**。我的处理是**不给 SPROUT 计时砍刀**，而是在 `CFG` 加一个旋钮：

```ts
/** 涌现段整体时间缩放。1.0 = S17 拍板过的手感，一行改小即可全局加速 */
SPROUT_TIME_SCALE: 1.0,
```

先按 1.0 上（不动你验收过的手感）。如果你实测觉得"等太久"，改这一个数就行（建议值 0.65 → 约 1.0s）。
**另外**：开场期间任意点击可跳过，直接跳到涌现。

### 修正 ②：首页的「重玩」与主按钮**语义重合**（决议 3）

必须说清一个事实：本作存档里只有 `cleared[]` 和 `bestTime`，**没有局内进度**。
所以当"重玩"和主按钮指向同一关时，**两者行为完全一样，其中一个会是废键**。

按你的决议（重玩 = 当前这一关）我的处理：

- **首页**：保留主按钮 + 88×88「重玩」小方。主按钮是**进入**（开始 / 继续 / 再战 · 第 k 关），
  「重玩」是**原地立刻再开一局**（跳过任何进入过渡，直接发牌）。
  当前这一关未开始过时，两者等价 —— 这是可接受的（不多一个页面、不多一个浮层）。
- **游戏页**：把「重玩」放成**常驻入口**，因为这才是它真正有用的地方。
  结算页原有的"重开本关"（`GamePage.ts:3540`）统一改名为 **「重玩 · 第 k 关」**，
  并在顶部信息条中轴加一枚同形制小方（打不过想重来，不必先退回首页）。

> **如果你要的是"重玩 = 再玩一次刚打通的那一关（第 clearedCount 关）"，说一声，我改这一处即可**（只动 `MenuPage` 一个回调）。

## 三、决议 5 展开：「碰 / 吃 / 杠」去术语 + 规则按钮

### 3.1 现状盘点：这三个字**出现在四个地方**，其中两处比首页文案重得多

| # | 位置 | 现状 | 严重度 | 处理 |
|---|---|---|---|---|
| 1 | `MenuPage.ts:96` 首页提示行 | `点击牌 → 进槽位 → 凑齐「碰 / 吃 / 杠」` | 中（静态文字） | **改文案** |
| 2 | `GamePage.ts:2501` **消除飘字** | **96px 金色大字 + 6px 墨描边**，每次消除都飘「碰」/「吃」/「杠」 | **🔴 最高** | **改字**（见下） |
| 3 | `GamePage.ts:2035` **消除音效** | `AudioService.play(m.type === 'chi' ? 'eat' : 'peng')` —— `peng.m4a` / `eat.m4a` 是**人声念白「碰」「吃」** | **🔴 高** | **换音源** |
| 4 | 代码注释 / 类型名（`MatchRule.ts` 等） | `MatchType = 'peng' \| 'chi' \| 'gang'`、`MATCH_LABEL` | 无（玩家不可见） | **保留**，只改注释措辞 |

**先说清第 4 条**：`peng / chi / gang` 是**纯内部枚举键**，不出现在任何玩家可见的位置。
重命名会牵动 `MatchRule` / `Generator` / `GamePage` / 求解器多处，**风险大于收益**。
所以：**类型名保留，注释与对外文案全部去术语化**（注释里说明"peng＝三张相同、chi＝同族连号、gang＝四张相同"）。
这条要在实施时写进 `MatchRule.ts` 头注释，避免下一个人看不懂。

**第 2 条（飘字）改法**——这是全局最醒目的一处，必须改：

| 方案 | 内容 | 评价 |
|---|---|---|
| **a（推荐）** | 飘字改成 **「消 除」** 二字，96px 金色大字、位置、动效、时长**全部不动** | 改动最小（只换字符串），保留 S12 做的"撞击 / 咀嚼"两套动效语汇 |
| b | 不飘字，改飘**图形**（扩散环 / 三道墨痕） | 丢失"读得出发生了什么"的信息量 |
| c | 飘数字 `+3` / `+4` | ⚠️ **不建议** —— 数字累加容易被读成计分 / 筹码，是本作明确规避的博弈语义 |

按 **a** 施工。落点：`MatchRule.MATCH_LABEL` 的**对外用途**改掉（飘字走一个新的中性 label 表），
内部 `type` 不动 —— 这样 `GamePage` 的取字逻辑只改一行。

**第 3 条（音效）改法**：

- `peng.m4a`（人声"碰"）→ **停用**，改播已有的 `clear.m4a`（碰撞后的消散，非语义，本来就和它组成二连）。
- `eat.m4a`（人声"吃"）→ **需要一个新音源**（约 0.3s 的纸 / 木质感"唰"，非语义）。
  用技能 `procedural-game-audio` 程序化合成，或从现有音效池里找可用的替代。
- ⚠️ 注意 `CFG.ts` 里已有注释：**别跑 `make-voice.py --install`**（音源是外部语音库）。
  这条要在实施时保留并改写（人声念白这条链路本次整体下线）。

### 3.3 规则浮层的**全部文案**（零术语，逐条可审）

| 位置 | 文案 |
|---|---|
| 标题 | `怎 么 消` |
| 副题 | `点牌进槽，凑齐就能消掉` |
| 案例① | **五筒 ×3**（真牌面）｜ `三张一模一样的牌，一起消掉` |
| 案例② | **一萬 · 二萬 · 三萬**（真牌面）｜ `同一族里号码连着三张，一起消掉` |
| 案例③ | **六筒 ×4**（真牌面）｜ `四张一模一样的牌，一起消掉` ＋ 小字 `第 3 关开始` |
| 脚注 | `万 · 条 · 筒 三族各自成串 · 不跨族` |

**说明为什么合并成一行**：原来"主文案 + 小字副行"两行的写法在 620 宽的卡片里，
三条案例各多占 30px，纵向撑到 840 以上；合并成一行后文案一个字没少（13~15 字，
26px 下最宽 390px，横向 540 绰绰有余），纵向省下 90px。

**为什么是这三条**：它们与 `MatchRule.findMatch()` 的判定**一一对应**（三张相同 / 同族连号 / 四张相同），
不多不少。脚注那句是必要的 —— `findChi()` 按族分组扫连号，**一萬 · 二条 · 三筒 永远消不掉**，
不写清楚玩家一定会试。

**用词红线**：不得出现 `碰 / 吃 / 杠 / 刻子 / 顺子 / 对子 / 胡 / 番 / 筹码 / 得分 / 连击 / 对局`。
上面表格里一个都没有。描述一律用**属性语言**："一模一样"、"号码连着"、"同一族"、"不跨族"。
（`消`字本身是通用动词，法院认定「消除」是通用名称 —— 见记忆里的命名雷区词表。）

**案例小牌怎么画**：直接调 `TileRenderer` 的牌面绘制，缩到 **80**（三张组）/ **72**（四张组）宽。
**零新资产、零新贴图**，浮层里出现的是一模一样的真牌面。
