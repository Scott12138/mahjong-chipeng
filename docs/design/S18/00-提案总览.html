《麻麻大消除》界面改版 · 三个方案

这一轮要做三件事：①首页参考折中布局但元素与色调都要换；②删掉选关页、改成直接开始 + 记录进度； ③每关加开场小动效，通关 / 失败各配一个"魔性"收尾。本阶段只出设计、不写代码—— 下面三份是三条刻意拉开的路线，不是同一套东西换三个颜色。

设计分辨率 720×1280 界面 100% 代码绘制（Cocos Graphics + Label） 贴图预算：三方案均为 0 张 包体 2.15 / 4 MB 已定稿资产：27 张真牌牌面（不得改）

一、三张首页稿并排 点开各自的 HTML 看完整稿（含坐标表 / 色板 / 动效分镜 / 成本）

A宣纸墨戏

在现有国潮体系里做到极致。成本最低、气质最静。

第一眼：一枚大牌立在墨色圆台上，顶部一条极细刻度条报进度，底部只有一颗朱红主按钮。
我的读感：最"高级"、最省，也最空——赌的是"比例与呼吸"，不加元素。

B灯影牌楼

借参考图1 的骨架，把它整套皮换掉。信息最完整。

第一眼：瓦檐 + 一串灯笼（亮 2 灭 2 = 进度）+ 六边形灯罩里的牌阵 + 主次两枚按钮 + 左侧两枚印章。
我的读感：最像一个"真正的游戏首页"，也最接近你要的折中布局；代价是元素最多。

C夜光牌局

最跳、最适合短视频传播，但离现有体系最远。

第一眼：夜蓝底 + 霓虹描边的三张牌在圆形准星里，进度做成霓虹管。
我的读感：差异化最强、合规最安全，但与 27 张真牌牌面不搭——作者自己实测后也是这个结论（见下表）。

三、三位专家各自独立提出的"共同结论" 与选哪个方案无关，建议一起拍

① 删选关页这一刀，比看上去深 —— 三份提案独立列出了同一张清单

要动的不是一个文件：删 ui/LevelSelectPage.ts（约 240 行）+ GameRoot.PAGE.LEVEL_SELECT + CFG.LEVEL_LAYOUT 整段（约 30 行），并清掉 4 处 goto('levelSelect') 调用 （MenuPage:92、GamePage:514 / 3448 / 3550）。 好消息是存档结构一个字都不用改 —— 现有 SaveService 的 cleared[] + bestTime 已经够用， 最多加一个 get clearedIds() 只读 getter（+3 行），不需要迁移、不需要升级版本号。

⚠️ 连带作废：S15.1 刚做完的"关卡页卡片排版优化"（CARD_* 那一整组常量）会随这一页一起删掉。 这是已经验收过的工作，删掉前请你确认一次。

② 现有文案里已经有一句棋牌语义，三份提案里有两位独立点了名

首页那行提示「点击牌 → 进槽位 → 凑齐「碰 / 吃 / 杠」」—— 碰 / 吃 / 杠 是麻将专有动作词， 与"零棋牌语义 / 申报休闲益智"是同一性质的提审风险。方案 A 的稿子里已经自动换成了 「点三张相同的牌，把它们送走」。建议无论选哪个方案都统一改掉。

③ 现存代码里已有一处 WCAG AA 不合规，与选哪个方案无关

CFG.COLOR.INK_SOFT = #8E8571 对宣纸底 #F2EADA 实测对比度只有 3.06 : 1， 却用在 20–22px 的小字上（版本号、说明行）—— 小字要求 ≥ 4.5 : 1。这条是现在就存在的，不是本轮引入的。 建议顺手修掉（往深里压一档即可，视觉上几乎看不出来）。

④ 「减弱动效」开关 —— 三位都建议留

微信小游戏拿不到系统的 prefers-reduced-motion，只能自己做。三份提案里的动效都有 闪白 / 抖动 / 粒子，属于容易引起不适的那一类。方案 A 已经把它写进 CFG（MOTION.REDUCED）。 建议：做一个总开关，开了就把"闪白、震动、粒子"降级为"淡入淡出"。

⑤ 开场动画与现有"从底部涌现"入场的关系，三份给的是不同答案

现在局内已经有一个「牌从目标下方涌现」的入场（S17 刚做完，1.6 秒 / 起点在目标下方 1.2 个牌高 / 起始缩放 0.45）。 新开场与它的关系有三种可能，需要你定：

  • 取代（方案 A 的判定）：开场替代涌现，棋盘直接"裂开"就位。入场等待更短，但 S17 的工作会被覆盖。
  • 前置叠加（方案 B 的判定）：先播新开场，再把涌现参数改写后接上 （1.2→0.9 牌高、0.45→0.48、1600→1000ms）。观感最连贯，代价是两次动效要接得上。
  • 并存但分工：开场只在每关第一次进入时播，重玩时直接涌现。

这一条直接决定"入场总时长"是 1.0s 还是 2.5s，也决定 S17 的成果留不留。

四、诉求 2 的落地规格 去掉选关页之后，用户从哪继续 / 怎么重玩 / 怎么清空

这一条三份提案的做法基本一致，可以直接定下来：

问题做法依据
从哪继续 首页主按钮 = 「继续 · 第 N 关」，N = 第一个未通关的关（在 cleared[] 里找第一个缺口）。 全 4 关通关后按钮语义变为"重玩"。 SaveService.cleared 已够用，无需改存档
怎么重玩 主按钮旁边（或下方）一个次要按钮。默认指向刚通关的那一关——那一关有最佳用时可刷，与"继续"正好互补。 A 为小方按钮 / B 为描边按钮 / C 为方形图标
怎么清空进度 长按该次要按钮 1.2 秒，再弹一条确认。两级保护，不新增按钮。 B 给了完整方案（含长按进度条）；A / C 同思路
进度的可见表达 首页顶部要能一眼看出"打到第几关了 / 已过几关"。三种表达：刻度条（A）／灯笼亮几盏（B）／霓虹管段数（C）。 三份都做到了，只是隐喻不同
⚠️ 三份提案在这一处有分歧，需要你定

「重玩」到底指向哪一关？方案 B 的稿子里画的是「继续闯关 · 第 3 关」+「重玩第 2 关」—— 也就是说它把"重玩"理解成重玩刚通关的上一关；方案 A 只写「重玩」，没指定。 我的建议是重玩"刚通过的那一关"（有最佳用时可刷，与"继续"不重复），但这是产品判断，你定。

五、请你拍板 按编号回答即可，比如"选 B，2 用前置叠加，4 同意"

  1. 选哪个方案？ A / B / C。 我的建议：B 做首页骨架最接近你说的"折中布局"，且信息最完整； 如果更看重"改得少、风险小、和现有牌面最搭"，选 A。
    另外允许组合：页面骨架用 A 或 B，通关那 1.2 秒单独借 C 的「熄灯爆点」—— 这是 C 的作者自己推荐的用法，四个好处里最实在的一条是成本极低（只在通关时多两块全屏色块的补间）。
  2. 开场动画与现有涌现的关系？ 取代 / 前置叠加 / 只在首次进入时播。这一条决定入场总时长是 1.0s 还是 2.5s，也决定 S17 的成果留不留。
  3. 「重玩」指向哪一关？ 刚通关的那一关（建议）/ 当前这一关。
  4. 金（GOLD）是否降级为"通关一次性事件色"？ A 提案提出、对 B/C 同样适用：不改色值，只改它出现的位置与生命周期，把"环境色"变成"事件色"。 这是本轮唯一一处真正动了合规风险的动作，也是低成本的。
  5. 统一改掉「碰 / 吃 / 杠」文案？ 建议：必须改（换成「点三张相同的牌，把它们送走」）。
  6. 顺手修 INK_SOFT 对比度？ 建议：修（现存问题，3.06:1 → 压到 ≥ 4.5:1）。
  7. 加「减弱动效」总开关？ 建议：加（有闪白 + 震动 + 粒子，属于容易引起不适的那一类）。
  8. 确认删掉选关页会连带作废 S15.1 的卡片排版成果 —— 这一条你已经明确要求了，我只是把它标出来免得事后意外。
