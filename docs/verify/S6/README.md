## 二、自动化验收结果

### 2.1 道具四件套 + 通关（正向链路）

```
d:0,-118  d:0,275  auto:2                 # 菜单 → L1 → 先消一组（让槽里有牌）
d:-89,-524  d:0,104  d:0,-96              # 移出 → 门禁 → 看广告 → 跳过
auto:1                                    # 回填一张，给「消除」用
d:-267,-524  d:0,104  d:0,-96  d:-299,-424 # 消除 → 门禁 → 广告 → 点槽内那张
d:89,-524   d:0,104  d:0,-96              # 洗牌
d:267,-524  d:0,104  d:0,-96              # 加槽
auto:60                                   # 打到通关
```

### 2.2 失败 + 复活（负向链路）

失败分支在真实游玩里很难稳定复现，所以给冒烟脚本加了一个**与 `auto` 相反**的动作
`dirty:<n>` —— 专挑"槽内张数最少"的牌面点，**绝不凑成 3 张**，槽位一满立刻判负。

```
d:0,-118  d:0,275  auto:40    # 清掉 L1，解锁 L2
d:0,85  dirty:24              # 进 L2 → 故意凑不成 → 逼出败局
d:0,60  d:0,104  d:0,-96      # 复活 → 门禁 → 广告 → 跳过
dirty:24                      # 再败（此时复活名额已用完）
```

**实测日志**：

```
[GamePage] 第 2 关 失败，已清 0/18，用时 7s，道具 消除0/移出0/洗牌0/加槽0，复活0
[GamePage] 失败面板已开 原因=槽位满了 可复活=true
[RewardGate] 渠道面板已开 → 选择=ad → 广告完成 → 放行 ok=true
[GamePage] 复活 第 1 次
[GamePage] 复活重排：第 2 次尝试，可解率 95%
[GamePage] 第 2 关 失败，已清 0/18，用时 15s，…，复活1
[GamePage] 失败面板已开 原因=槽位满了 可复活=false
```

| 指标 | 结果 |
|---|---|
| 判负原因 | `槽位满了`（`dirty` 策略精确命中） |
| 首次可复活 | `true` ✅ |
| 复活效果 | 槽内牌**退回场上** + 自动洗牌，`可解率 95%` |
| 二次可复活 | `false` ✅（每关 1 次，名额约束生效） |

### 2.3 牌面尺寸与包体积

| 指标 | 改前 | 改后 |
|---|---|---|
| 牌面（牌堆） | 64 × 85 | **128 × 171**（2.00× / 2.01×） |
| 菜单展示牌 | 104 | 120 |
| 关卡卡片小牌 | 92 | 108 |
| 关卡张数上限 | 90 | **24**（牌堆区只放得下 28 格点） |
| 微信 release 包 | 2.9 MB | **3.0 MB**（红线 4 MB） |

> 张数下降**不是难度设计变了**，是牌面放大后算出来的容量上限：
> 牌堆区 588×664，牌 128×171，纵向格距 171×0.48 ≈ 82
> → 横向 4 列、纵向 7 行 = **28 格点**。90 张牌在这个尺寸下根本落不了位。
> 难度改由 `patterns`（6/8/9 种牌面）与 `solveRate`（解路径宽窄）承担。

## 三、本阶段修掉的缺陷（都是实跑才暴露的）

| # | 现象 | 根因 | 修法 |
|---|---|---|---|
| ① | 渠道面板的合规小字被广告按钮压住一半 | 副标题在 `TITLE_DY−54`，而按钮上沿只比它高 2px，按钮后画 → 盖住 | 面板加高 36px（404→440），四行依次拉开，净空 ≥9px |
| ② | 失败面板「看广告复活（清空槽位 + 洗牌）」**末字被裁** | 400px 按钮装不下 13 个全角字（13×34 = 442 > 400） | 文案收短为「看广告复活（清槽 + 洗牌）」，按钮 400→448，字号 −12 |
| ③ | 失败面板大标题与副标题只剩 3px，视觉上贴在一起 | `PANEL_H=384` 太挤 | 面板加高 36px（384→420），标题上移、副标题下移 |

> 这三个缺陷**都不是逻辑错误**，任何"只看日志"的验证都发现不了 ——
> 它们是这一阶段引入「截图留痕」这件事本身的回报。

## 五、已知待优化（不影响可玩性）

1. **「消除」的两段式交互有学习成本**：点按钮后还要再点一次槽内牌。
   已用金色按钮 + 副标签「点槽内一张」提示，但首次仍可能愣一下。
   S7 可考虑加一个指向槽位的箭头动效。
2. **`dirty` 逼出的败局偏"人工"**：真实玩家不会这么玩，
   所以「槽位满了」这个判负原因的**真实出现频率**还没数据，等灰测。
3. **本次未做微信端实机验证**：`web-desktop` 与微信版共用同一份逻辑，
   但 `wx.createRewardedVideoAd` / `wx.shareAppMessage` 这两条真实通道
   **尚未在真机跑过**（模拟广告与真广告收敛在同一个 `settle()`，
   结构上"填 ID 即生效"，但仍需一次真机确认）。
