## 二、自动化验收结果

`tools/web-smoke.mjs` 的 `auto:<n>` 动作 —— 从游戏自报的日志里读「可点牌」坐标自动试玩。

```
d:0,-118        # 菜单 → 点「开始游戏」
d:0,275         # 关卡页 → 点第 1 关
auto:26         # 自动试玩
```

**实测结果（L1 完整通关）**：

| 指标 | 结果 |
|---|---|
| 生成 | 18 张牌 / **1 次采样即命中** / 可解通过率 **100%** |
| 自动点击 | 18 次，状态变化 18 次（每次都有响应，无空点） |
| 消除 | **6 组全中**（碰），`已清 0→3→6→9→12→15→18` |
| 结局 | `第 1 关 通关，已清 18/18` ✅ |

**L2 / L4 生成质量**：

| 关 | 牌数 | 采样命中 | 可解通过率 | 生成耗时 | 开局可点 |
|---|---|---|---|---|---|
| L1 试手气 | 18 | 1 次 | 100% | — | 17 |
| L2 上道了 | 60 | 1 次 | 55% | — | — |
| L4 就差一点 | 90 | 1 次 | 68% | **69ms** | 11 |

> 「可解通过率」= 60 局随机化贪心模拟里能通关的比例。
> 越接近 0 → 解路径越窄 → 越难。S5 难度标定会用它做量化依据。

## 四、已知待优化（不影响可玩性）

1. **DrawCall 偏高**：L2（60 张）约 122，L4（90 张）约 176。
   每张牌一个 `Graphics` + 万子还有两个 `Label`，都属于独立渲染节点。
   低端机可能有压力，S8 性能专项处理（方向：被压住的牌降级绘制 / 动态合图）。
2. **牌堆轮廓偏方正**：L4 密度 80%，看起来接近一个方块，"山形"不明显。
   可通过调 `STACK.WEIGHT_X / WEIGHT_Y` 增强，属于 S5 难度标定的调参范围。
3. **被压住的牌几乎只露一条边**：这是叠塔消除的固有难度来源（本来就该看不清），
   但要留意别调过头 —— 如果玩家完全无法规划，挫败感会超过挑战感。
