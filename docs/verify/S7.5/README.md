## 1. 「碰」的撞击 —— 8 帧过程（`01-碰-撞击全过程.png`）

裁切区域 = 槽位条左半（设计坐标 `-355,-500 → -5,-350`），放大 2.4×。

| 偏移 | 画面 | 对应参数 |
|---|---|---|
| 300ms | 两张已在槽内，第三张还在飞 | `PICK_SELECT=0.18s` + `flySec≤0.30s` |
| 400ms | 三张并排，正常槽格间距，金色选中描边 | `PICK_SCALE=1.12` |
| 460ms | 三张开始**向中间聚拢**，间距缩小 | `CLASH_ANTICIPATE=0.09s` 蓄力 |
| **520ms** | **三张重叠成一摞**，牌面被横向压扁，撞击点出现金色颗粒 | `EASE_DASH='quadIn'` 冲刺到位 + squash `0.84×/1.16×` + `burstAtTile` |
| 580ms | 仍是叠合状态，中心爆出**金色冲击圆环** + 碎屑四散 | `CLASH_RING_R0/R1=18/96`、`CLASH_RING_LIFE=0.24s` |
| 650ms | 槽位已空 | `POP_HOLD=0.06s` 停一拍 → `POP_OUT=0.24s` 胀到 1.20 再缩到 0 |
| 730 / 850ms | 完全清空 | — |

**结论**：用户要的"三张牌碰在一起，**然后**消除"在时间轴上真实成立 ——
520ms 时三张确实叠成一摞（`CLASH_OVERLAP_PENG=0.45 × 槽格宽`），
消除发生在 650ms（撞击之后，不是同时）。

## 6. 本轮修掉的缺陷（都由实测暴露）

| 缺陷 | 症状 | 根因 |
|---|---|---|
| **不限时关卡的判负原因恒为「时间到」** | 第 1 关界面写着"不限时"，槽位塞满判负，面板却说"时间到" | 结算页用 `this._timeLeft <= 0 ? '时间到' : '槽位满了'` 反推，而**不限时关卡 `_timeLeft` 恒为 0**。→ 改为由判负入口写入 `_failReason`（`'slotfull'` / `'timeout'`）。见 `05-失败面板-槽位满了.png` |
| **引擎性能面板盖住槽位条** | 「碰」的整段动效被 FPS/Draw call 面板遮住，开发时看不到 | web 模板把 `showFPS` 写死为 `true`，且面板固定画在左下角 = `SLOT_BAR_Y=-424` 那片区域。→ 新增 `CFG.DEBUG.STATS`（默认 false）+ `Bootstrap.applyStats()` 运行期收掉，**必须 try/catch**（该 API 在 `director.root` 就绪前会抛异常，而异常会中断整个模块 → 游戏白屏）。见 `06-主界面-性能面板已收掉.png` |

## 7. 未验证项（明确记录，不含糊）

| 项 | 原因 | 下一步 |
|---|---|---|
| **震动手感** | 浏览器没有 `wx.vibrateShort`，web 端只走 `navigator.vibrate` 兜底（无头环境无触感） | **必须真机确认**：三档强度是否区分得出来、iOS 是否太弱 |
| **音效听感** | 无头环境无音频输出，只能确认"资源加载成功 + 声道池正常" | 真人试听；若某段过于抢耳，改 `AUDIO` 段的 gain |
| 真实广告 / 分享通道 | 一直走的是模拟分支 | 提审前真机跑一遍（S8） |
| `可点=0` 且槽未满时的暂存架指引 | 「移出」道具把 3 张牌放进暂存架后可能出现，逻辑上不会死锁（可取回），但提示语没指引 | 见 DESIGN §11 新增行，**待拍板** |

## 8. 测试环境陷阱（写给以后的自己）

**无头 Chrome 会把后台/被遮挡窗口的 `setTimeout` 节流到 1 秒。**
本工程铁律是"状态流转只走 `setTimeout`"，于是所有落位 / 解锁 / 结算定时器被拉长到 ~1000ms。
表现极具误导性：设计上「拿牌 → 441ms 后落位」，实际 1000ms 才落位，
自动化每 800ms 点一次就撞进飞行窗口 → 被 B7 判成"点错了、撤回"，
日志里只剩

```
拿牌 id=10 … 落位倒计时 500ms
取消选中 …
落位放弃 id=10：挂起态已不属于本次拿牌（_pending=null）
```

的循环 —— **看起来像游戏有 bug，实际是测试环境把定时器改了**。
`tools/web-smoke.mjs` 已加 `--disable-background-timer-throttling
--disable-backgrounding-occluded-windows --disable-renderer-backgrounding`，
修好后同一用例 `落位放弃: 0 / 取消选中: 0`。

排查这条时新增的两条面包屑（`CFG.DEBUG.LOG_STATE` 控制）值得保留：
`拿牌 id=… 选中 180ms + 飞行 300ms → 落位倒计时 500ms` 与
`落位放弃 id=…：<原因>` —— **拿牌到落位的时长一旦超过玩家两次点击的间隔，
就会退化成"点一下、撤回一下"的死循环，而现象完全看不出是时长问题**。
