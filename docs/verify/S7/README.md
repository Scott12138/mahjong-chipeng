## 4. 独立代码审查（本轮真正的收获）

冒烟测试只能证明**逻辑通路正常**，证明不了**动效真的播了**。
本轮请了一位独立审查者（只读、不看构建结果）复看 1117 行新增代码，抓到 3 个真实缺陷 ——
**这 3 个在自动化冒烟里全是绿灯**。

| # | 严重度 | 缺陷 | 症状 | 根因 | 修复 |
|---|---|---|---|---|---|
| F2 | P1 | **入场缩放动画实际没播** | 牌堆停在 0.94，直到解锁时"啪"地跳回 1.0 | 缩放补间与淡入补间**共用同一个 tag**，而 `MotionFx.launch()` 第一步就是 `stop(key, tag)` → 后起的淡入把刚起的缩放当场停掉 | 淡入改用 `TAG.FADE`（与 A4 的写法对齐） |
| F1 | **P0** | **同一张牌同时在场上和槽内** | 槽位占用虚增（可能误判"槽满判负"）、`_left` 虚高（本关永远清不完） | `pickTile` 的落位定时器不校验"这次落位是否还属于当前这次拿牌"；玩家在 ~380ms 飞行窗口内再点同一张牌触发取消，`cancelPick` 已把 `_taken[id]` 还原成 false，定时器到点却仍把牌 `splice` 进槽 | 落位前加**归属校验** `if (!this._pending \|\| this._pending.id !== id) return;`，并在视图失效分支里补上数据还原 |
| F3 | P1 | **洗牌收尾抢走别人的输入锁** | 两条链路同时改槽位数据，槽内顺序随机错乱 | 收尾定时器写 `if (!this._pending) this._busy = false;`，判据只覆盖"拿牌"，**覆盖不到"道具"**（道具不置 `_pending`） | 收尾定时器**完全不碰 `_busy`**（提前解锁那条定时器必然先触发，锁早已放过） |
| N1 | P3 | **兜底回收比显式回收更早**（F4 的修复引入的新问题，第 2 轮抓到） | 奖励图标在到位前约 20ms 被强制回收（人眼约 1 帧） | `FX_MAX_LIFE=0.40s` **短于** `REWARD_FLY=0.42s` | `autoRecycle` 增加可选寿命参数，调用处显式传 `REWARD_FLY + FX_MAX_LIFE` |

**两轮结果**：第 1 轮 `IS_PASS: NO` → 修复 F1/F2/F3/F4 → 第 2 轮 `IS_PASS: YES`。
（F5–F8 属 P2 建议，未在本轮修，见 §6 待办。）

## 5. 仍需真机人工确认的点

自动化只能验到"逻辑通"，手感本身必须靠眼睛：

1. **入场时牌堆的 0.94→1 缩放与淡入是否都完整播完**，不再出现"解锁瞬间啪地跳回 1.0"（F2）。
2. **飞行途中点同一张牌取消（B7）后**，牌是否稳定退回原位、槽位计数与"剩余数"无虚增；
   取消后立刻点另一张牌是否正常（F1）。
3. **洗牌全流程**（含最后 100ms 提前解锁窗口内点牌）是否无错帧，且结束后输入锁确已释放；
   反复点道具是否会出现"两条链路同时改槽位"（F3/N1）。

**踩过的坑（会重复踩，务必记住）**：

- **macOS 没有 `timeout` 命令**。用 `timeout 150 node ...` 包装时，命令根本没执行，
  而 `grep` 会把 "command not found" 过滤掉 —— **看起来像通过了**。
  本机请改用工具自身的超时参数，不要套 `timeout`。
- **构建产物必须验新旧**：只看"构建成功"不够，要 grep 产物里是否含新标识符
  （如 `MotionFx` / `ARC_SEGMENTS` / `playEnterMotion`）并核对 mtime。
- **`build-script` 出现 `signal:SIGTERM` 不等于构建失败**：那是 `tsc` 报完既有的
  `padStart` 错误后被中止，转译产物照常生成（用上一条核实）。
- **连续跑冒烟要先清 CDP 环境**：`rm -rf /tmp/cocos-cdp-profile`，否则 9333 端口
  可能被上一轮残留的无头 Chrome 占住。
