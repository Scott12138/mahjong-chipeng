## 2. 逐关证据

### L1「试手气」· 12 张 · 固定教学牌组

```
[GamePage] 第 1 关「试手气」：12 张牌 / 1 次采样 / 已认证可解（可解率 100%）/ 生成耗时 13ms
[GamePage] 消除 牌型=peng(碰) 张数=3 → 动效=撞击 ｜ wan-5 wan-5 wan-5
```

- **不学会「吃」就过不去**：固定牌组 = 2 碰组 + 2 吃组。先把两组「碰」消掉后，
  场上剩 1万×2、2万×2、3万×3 —— 「碰」再也凑不成，唯一通路是连续两次「吃」。
- 平铺 12 张全可点 → **不可能失败**，玩家在零压力下学会「吃」。
- `05-吃-流水汇合中间帧.png` 是「吃」动效（流水汇合）的撞击帧连拍，
  由 `dirty` 动作强制凑「吃」抓取（`dirty` 永不凑「碰」，见 `tools/web-smoke.mjs`）。

### L4「就差一点」· 96 张 · 终局

```
[GamePage] 第 4 关「就差一点」：96 张牌 / 16 次采样 / 仅认证开局不卡（可解率 0%）/ 生成耗时 121ms
[GamePage] 第 4 关「就差一点」：96 张牌 /  3 次采样 / 已认证可解（可解率 5%）/ 生成耗时 46ms
[GamePage] 牌局 已清=0 槽=0/8 槽内=[] 暂存=[] 可点=5 ｜ sou-6@218,316 …
```

两次不同种子都跑通，且**恰好演示了三档契约的两档**：

| 档 | 实测 | 说明 |
|---|---|---|
| ① 认证可解 | 3 次采样命中，可解率 5% | 顺滑区帮它在低概率下也能被抓到 |
| ② 认证开局不卡 | 16 次采样落空，可解率 0% | 兜底交付；开局仍有 5 张可点 |

- ②档下**生成耗时涨到 121ms**（①档只要 46ms）—— 因为它要试满
  `SOLVE_SEARCH_RETRY = 10` 次才放弃。仍在可接受范围（<200ms），
  但这是目前四关里唯一一处"进关卡时肉眼可能察觉"的耗时，**真机试玩时留意一下**。

## 3. 性能（L4，96 张，最重局面）

`metrics-L4-perf.json` 的原始采样（6 次）：

| 指标 | 值 |
|---|---|
| 峰值 draw call | **186**（6 次采样完全一致，无抖动） |
| 平均帧耗时 | **16.68 ms** |
| 推算 FPS | **60**（浏览器 vsync 上限） |

- 采样方法已固化进 `tools/web-smoke.mjs`：跑到目标关卡后连读 6 次
  `director.root.device.numDrawCalls` 取峰值，结果写进 `metrics.json` 的 `perf` 字段。
- ⚠️ **`numDrawCalls` 每帧清零**，只读一次可能撞上清屏后的帧 —— 所以必须取峰值。
- 对照：菜单页只有 29 draw call。**96 张牌的真实开销在 186**。

## 4. 复现命令

```bash
# 0) 构建（web-desktop debug 用于冒烟，微信 release 用于真机）
bash tools/cocos-build.sh web-desktop debug game-4-mahjong
bash tools/cocos-build.sh wechatgame release game-4-mahjong

# 1) 类型检查
bash tools/tscheck.sh

# 2) 逐关冒烟（一条命令内含 起服务器→无头点击→收服务器）
bash tools/smoke-run.sh web-desktop /tmp/t4-l1        "d:0,-118" "d:0,275" wait:900  "auto:20"
bash tools/smoke-run.sh web-desktop /tmp/t4-l2 unlock:1 "d:0,-118" "d:0,85"  wait:1200 "auto:30@420"
bash tools/smoke-run.sh web-desktop /tmp/t4-l3 unlock:2 "d:0,-118" "d:0,-105" wait:1200 "auto:45@420"
bash tools/smoke-run.sh web-desktop /tmp/t4-l4 unlock:3 "d:0,-118" "d:0,-295" wait:1200 "auto:60@420"

# 3) L1「吃」动效连拍（dirty = 永不凑碰，逼出「吃」）
bash tools/smoke-run.sh web-desktop /tmp/t4-l1-dirty "d:0,-118" "d:0,275" wait:900 "dirty:12!150,300,450"

# 4) 真机预览二维码
#    ⚠️ 输出目录要放在「真目录」里 —— macOS 的 /tmp 是软链接（→ private/tmp），
#       CLI 的父目录校验不认软链接，直接写 /tmp/qr.png 会报 `二维码输出路径无效或不存在 (code 17)`。
mkdir -p /tmp/s10-preview          # 新建的子目录就 OK；或直接用 /private/tmp/...

  --project "$PWD/game-4-mahjong/build/wechatgame" \
  --qr-output /tmp/s10-preview/preview.png
```

> `d:<x>,<y>` 是**设计坐标**（原点 = 屏幕中心、y 向上），与 `CFG` 里的布局常量一一对应，
> 读代码即可写测试，不用量像素。
> 关卡卡片的 y：L1 `275` / L2 `85` / L3 `-105` / L4 `-295`（`LEVEL_LAYOUT` 的
> `FIRST_CARD_Y=275`、行距 190）。

## 5. 本轮踩到并已修掉的问题

| 问题 | 现象 | 修法 |
|---|---|---|
| 顺滑区总是抓走全部「吃」组 | L2 通关率仅 16%、开局早卡 20% | 取顺滑区**前先打乱组序** → 通关率 61%、早卡 6% |
| `chiGroups` 起始点取到 8/9 | 会拼出不存在的 `wan-10` | 限制 `start ∈ 1..7` |
| L1 平铺关纵向抖动过大 | 12 张里只有 10 张可点 | 平铺关单独用 `JITTER_FLAT = 3` |
| 四向随机后槽内牌看着像渲染 bug | 180° 牌倒着、90° 牌躺着 | 做成开关 `STACK.SLOT_KEEP_ANGLE`，**等真机试玩后定去留** |
| 洗牌在大牌数下 100% 失败 | 玩家看完广告什么都没发生 | `RESHUFFLE_REQUIRE_SOLVABLE = false`，退化为"最好的一版" |
