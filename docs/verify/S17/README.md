## 一、调研：抓大鹅的开局到底是怎么做的

本机原先没有取帧/下载工具，临时装了 `yt-dlp` + `imageio-ffmpeg`（后者自带静态 ffmpeg）。
下载 3 支**原版**录屏（排除"菜市场抓大鹅"一类换皮仿品）→ ffmpeg 抽帧 → 15/20/30fps 逐帧比对。

| 场景 | 视频 | 开局出现窗口 |
|---|---|---|
| 麻将桌（道具就是麻将牌） | `BV1Mm41127v8` | t≈1.35s → 2.70s |
| 轻食碗 | `BV1mwtn6zEw5` | t≈3.10s → 5.60s |
| 火锅铁锅 | `BV1R3p7zEEvQ` | t≈4.65s → 7.30s |

**三个场景口径完全一致**：

1. 空容器先亮 **0.5~1.3s**（还挂着"即将开始"按钮）—— 先给一个起手空拍；
2. 物件**很小地**从容器**上方**下来，边落边变大（3D 透视的"由远及近"）—— 这是掉落感的核心；
3. 落点**不成行**，像倒一盆东西：中间先堆、再向四周漫开、互相叠压；
4. 先落的沉在底下 → **"自底向上"是落体顺序的结果，它的运动方向是向下的**；
5. 总时长 **≈1.3~2.5s**，落地有弹性，落定后留一小段静置才开表。

> 证据帧：`temp/S17-抓大鹅开局参考/`（6 张关键帧 + `分析.md`）。
> `temp/` 已在 `.gitignore` —— **第三方截图不入库**，只作本次调研的临时留档。

### 我错在哪（S16 复盘）

| 我的实现 | 实际应该是 |
|---|---|
| 把"自底向上"当成**运动方向** → 每张牌从自己脚下钻出来 | "自底向上"是**落体顺序的结果**；方向只有一条：从上往下（本作反转为从下往上） |
| 错峰按**屏幕 y 分"田垄"** → 整齐的水平条带、一批一批往上顶 | 散乱的簇 —— 抓大鹅的观感是"一撮一撮"，不是"一条一条" |
| 结果像"电梯上升 / 春笋冒头" | 应该像"从锅底散乱地涌上来" |

### 一个方向性事实必须先说清

用户原话是"从**底部**涌现"，而实测抓大鹅是"从**上方**倒入" —— **方向相反**。
所以方案 B 的定义是：**保留本作"从下往上"的方向**，只借抓大鹅的**物理感**。

## 二、方案 B 的实现

### 2.1 错峰：田垄 → 随机成束（四步）

```
① 洗牌随机撒"束心"      （束数 = 张数/6，夹到 3~6；洗牌而非"随机抽到不重复"，保证必然终止）
② 每张牌归最近的束心     （欧氏距离）→ 得到的簇散落在牌堆各处，不是横竖的条
③ 束按束心高度自下而上排 （"成束"管散、"排序"管方向，分开管才有"既有方向又不整齐"）
④ 束内按到束心的距离铺开 （从中心往外依次拱出）
```

- ④ 是**必要的**：L3/L4 每束 10~16 张，束内若完全同时冒，整堆会退化成
  "6 次大队列齐射"，成束感反而消失。
- ⚠️ 顺序改了，**绘制顺序（`siblingIndex`）仍然按 `depth`** —— 两者混为一谈才是真 bug。

### 2.2 参数（`CFG.MOTION`）

| 参数 | 旧（S16） | 新（S17） | 说明 |
|---|---|---|---|
| `SPROUT_IN` | 0.42s | **0.52s** | 单张升程 |
| `SPROUT_SCALE_FROM` | 0.42 | **0.45** | 起始缩放（"还没长开"） |
| 错峰 | 田垄分带 | **随机成束** | 新增 `BURST_SIZE/MIN/MAX/GAP/JITTER/RING`，删 `BAND_GAP/SWEEP_X/BAND_MAX` |
| 落位 | 两段 | **三段** | 挤压 → 回弹过冲（`SPROUT_BOUNCE=1.07`）→ 归位 |
| `SPROUT_SQUASH` | 0.12s | **0.24s** | 0.12s 塞三段每段只有 40ms，只会看到"抖了一下" |
| `SPROUT_TOTAL_MAX` | 1.0s | **1.6s** | 整段上限 |
| 实测总时长 | 0.75~0.83s | **1.53 / 1.60s** | 实测抓大鹅 1.3~2.5s，本作取偏快的一端 |

### 2.3 ⚠️ 踩到的一个坑：`TOTAL_MAX` 的口径

第一版算束间距时**只扣了单张升程**，实测 L2~L4 跑到 **1.84s**（超预算 15%）。
修正为扣 `升程 + 落位回弹 + 束内抖动 + 束内铺开` → 精确停在 **1.60s**。

### 3.2 编排数据图（`截图/03-错峰编排对比图.png`）

把每张牌的**冒出时刻 × 牌在牌堆里的高度**画成散点（L4，96 张，固定种子）：

- **左（S16 田垄）**：所有点挤在前 400ms、呈**阶梯状**，颜色**严格按高度分层**，
  批次之间有明显水平间隙 → 这就是"整齐条带"。
- **右（S17 成束）**：时间散布到 800ms，**同一高度上混着不同束的牌**，
  但"低处的束仍先冒" → **条带被打破、方向保住**。

> ⚠️ **无头截图验不了"编排"**：CDP `Page.captureScreenshot` 有几十~几百 ms 抖动，
> 连拍的相位不可控（同一串动作、不同次运行抓到的相位都不同）。
> 所以本节改用数据图 —— 这是本次最可靠的一条证据。

### 3.3 入场连拍（`截图/01` / `02` / `04`）

L1（12 张、3 束，最容易看清）：第 5 帧先冒出左侧**一小撮**（伍萬/八萬/三萬），
第 6 帧再补一撮 → "一撮一撮"可见。

### 3.4 玩法回归（`log/regress.log` + `regress-metrics.json`）

进关后自动试玩 12 步：拿牌 / 落位 / 入槽全部正常，L1 开局可点 12，
**61 FPS / 46 draw call / 可见尺寸 720×1280** ✅。
