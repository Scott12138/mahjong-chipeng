## 1. 问题①：「吃」的特效

### 1.1 现状（读代码得到的事实）

两条消除路径的**表现清单对照** —— 差异比想象中大得多：

| 表现元素 | 碰 / 杠（`onClash`） | 吃（`playFlowClear`/`releaseFlow`） |
|---|---|---|
| 牌的运动 | 三张**同时**：先远离中心退 12px 蓄力 → `quadIn` 向心猛冲 | 三张**依次**滑向中心（错峰 70ms，各 300ms） |
| 到位的处理 | 到齐 → 挤压 squash&stretch | 到齐 → **停 50ms** |
| 冲击圆环 | ✅ `spawnPulse`（r 18→96） | ❌ 无 |
| 碎屑 | ✅ 每张牌各喷一次 `spawnDebris` | ❌ 无 |
| 牌堆反馈 | ✅ `kickStack()` 上踢 5px | ❌ 无 |
| **飘字** | ✅「碰」96px 金边大字 | ❌ **无** |
| 消散方式 | 胀到 1.20 → 缩到 0 + 淡出 | 一律上浮 22px + 淡出（**不缩放**） |
| 音效 | `peng`（和弦）+ 70ms 后 `clear` | `flow`（滑音） |
| 震动 | 中档 | 中档 |

> **结论**：用户说"吃没有碰那样的特效"，事实比这更严重 —— **「吃」连「碰」有的飘字都没有**。
> 现在的「吃」= 三张牌挪到一起 + 淡出，仅此而已。

### 1.2 「小黄人吃豆子」到底由什么构成

把 Pac-Man 吃豆的那一瞬间拆开，**只有三个要素**（多一个都不是它）：

1. **张嘴** —— 嘴先张开，豆子才被吃
2. **一口一个** —— 豆子**依次**被吃，有节奏；不是一次吞完一片
3. **即触即消** —— 嘴碰到豆子**那一帧**豆子就消失，不是"吸进去再慢慢化掉"

### 1.3 方案：「一口一个」的咀嚼式消除

**★ 核心改动（本方案最值钱的一条）**
> 现在：三张牌**全部到齐** → 停 50ms → **一起**淡出 —— 整个「吃」只有 **1 个**节奏点。
> 改成：**每张牌到达嘴边的那一帧就被咬掉** —— 整个「吃」变成 **3 个**节奏点：咔、咔、咔。
>
> 这一条不需要任何新美术资源，纯时间轴改动，但它是"吃"和"碰"在**体感**上分开的关键。

**表现清单**

| 代号 | 元素 | 具体做法 | 表达的语义 |
|---|---|---|---|
| **A** | **吸力曲线** | 滑行曲线由 `sineInOut`（匀速柔滑）改为「前段几乎不动（被吸住）→ 后段突然加速被吞」。实现：`EASE_IDLE` + `FLOW_SLIDE` 缩短到 0.22 | 被**吸**进去，不是漂过去 |
| **B** | **咬合颚片** | 目标点出现一对**上下弧线**（上下颚）：牌到达前 60ms 张开 26px → 到达那一帧合拢。**矢量画，零贴图** | 嘴 |
| **C** | **逐张咬消** | 第 k 张到位瞬间：`scaleY` 压到 0.55 + 短促消失（90ms）+ 一声音效 + 一个小脉冲 | 一口一个 |
| **D** | **咀嚼残渣** | 每口在嘴边喷 **4 个小方点**（**方**，不是碰的**圆**碎屑）向外弹散 | 嚼碎了 |
| **E** | **打嗝收尾** | 三口吃完后：中心上浮一个小脉冲 + **飘字「吃」** + 牌堆轻微上踢（复刻 `kickStack`，幅度减半） | 吞下去了 |
| **F** | **节奏** | 每口间隔 `EAT_BITE_GAP = 0.12s`，三口共 ≈ 0.5s | 吃得快 = 香 |

### 1.4 必须守住的「碰 / 吃」差异（否则两个牌型会合并成一种体感）

> 这是本方案的设计底线。**不是"碰有特效、吃没特效"，而是两者用不同的语汇。**

| 维度 | 碰 / 杠 | 吃 |
|---|---|---|
| 牌的运动 | **同时**（三张一起动） | **依次**（错峰） |
| 方向 | 先**后退**蓄力 → 向心猛冲 | 直接被**吸**向一个点 |
| 到位处理 | 到齐后**一起**挤压 + 炸开 | **一张到位就咬掉一张** |
| 特效形状 | **圆**（冲击环、圆碎屑） | **楔 / 弧**（上下颚、方残渣） |
| 冲击强弱 | **硬**（squash 0.84/1.16 + 环 96px + 上踢 5px） | **软**（小脉冲、残渣小、上踢 2.5px） |
| 音效 | **一声**"咚"（和弦） | **三声**"咔嚓"（有节奏的咀嚼） |
| 收尾 | 胀到 1.20 再缩到 0 | 上浮 + 打嗝小脉冲 |
| 震感 | 中档 | 中档（首口）+ 轻档（后两口） |

### 1.5 ⚠️ 代价说明 —— 这条推翻了 S7.5 的一条设计原则

`CFG.ts` §十五 现在有整段论证，原话是「**丝滑是减出来的，不是加出来的**」，
并明确把「不加挤压 / 不加冲击环 / 不加碎屑 / 不加牌堆上踢」列为「吃」的**设计正确性**而非常规疏漏。

本方案**推翻它**。我的判断是这次推翻是**对的**，理由：

- S7.5 的出发点是"用户要一个'丝滑'的吃"，于是把撞击的语汇全拿掉 —— 结果**把"动作"也一起拿掉了**，剩下"位移+淡出"，玩家读不出"吃"这个动作。
- 正确解法不是"加"或"减"，而是**换语汇**：用「吸 + 咬 + 嚼」表达吃，用「蓄力 + 撞 + 炸」表达碰。两者都有完整特效，但**没有一个元素是共用的**。

### 1.6 分档（可只取一部分）

| 档 | 含 | 观感 | 工作量 |
|---|---|---|---|
| **① 精简** | A + C + E（吸力 + 逐口咬消 + 飘字「吃」） | 已经有"一口一个"的节奏，但缺"嘴"这个具象 | 小 |
| **② 全套（推荐）** | A + B + C + D + E + F | 完整"张嘴→咬→嚼→打嗝" | 中 |
| **③ 渐进** | 先做① 真机看 → 再决定加不加 B/D | 风险最低 | 小 → 中 |

## 2. 问题②：魔性音效

### 2.1 现状事实

| 项 | 事实 |
|---|---|
| 来源 | **全部由 `tools/make-sfx.py` 程序化合成**（正弦 / 噪声 / 扫频 / 包络四种基元），**没有任何人声** |
| 体积 | 13 段共 **156KB**（AAC 64kbps 单声道，每段 4~8KB） |
| 版权 | ✅ **100% 干净**（自己合成的，来源完全可追溯） |
| 可复现 | ✅ 固定随机种子 + 清零 m4a 容器时间戳（同脚本重跑逐字节一致） |
| 「碰」的配方 | 冲击瞬态噪声 + 三音和弦 C-E-G（523/659/784Hz） |
| 「吃」的配方 | 上行滑音 523→1046Hz + 低通噪声 + 柔和泛音，attack 拉到 12ms（碰是 3ms） |

### 2.2 ⚠️ 关于"上网找四川话音效"，三条必须先说清的硬事实

1. **找不到**。CC0 / 免费库里的方言录音基本是**成句**的，没有"碰""吃"这种单字短音；即便有，**授权链条往往不清**。
2. **这是拒审的第一大原因**。微信小游戏审核要求所有音频素材有完整著作权或合法授权；行业统计里「游戏内存在未授权音乐」占拒审原因的 **32%** —— 典型情形正是"从免版权站下载的素材，实际版权方已商用收费"。你是**个人主体 + 要办软著 + 版号未解决**，再叠一条音效授权瑕疵，性价比很低。
3. **方言 TTS 也没有四川话**。微软 edge-tts 的中文方言**只有** `zh-CN-liaoning-XiaobeiNeural`（辽宁话）和 `zh-CN-shaanxi-XiaoniNeural`（陕西话）；本机 macOS `say` 只有普通话（Tingting 等）与粤语/台语，**无四川话音色**。而且白嫖 Edge TTS 服务用于商用产品**不符合其服务条款**。

### 2.3 三条可选路径

| # | 路径 | 地道度 | 版权 | 需要你做什么 |
|---|---|---|---|---|
| **①** | **你自己录**（手机录 3 条四川话：「吃～」「碰！」「吃嘛」） | ★★★★★ | ✅ 100% 干净 | 3 分钟 |
| **②** | **我自制"拟方言人声"合成**（扩展 `make-sfx.py`，共振峰合成） | ★★★ | ✅ 干净（同现有路线） | 无 |
| **③** | 用 edge-tts 的**东北话 / 陕西话**念「吃」「碰」 | ★★★★ | ⚠️ ToS 风险 | 无 |

**① 的做法**：你录 3 条（随便什么手机，安静环境即可）→ 我负责降噪、裁切、变调、归一化、转 m4a 入库。
代码**一行不改**（音效 id 不变，只换文件）。素材体积 +约 24KB（3.2MB → 3.22MB，红线内）。

**② 的做法**：用**源-滤波器模型**造音节 —— 脉冲声源（模拟声带）→ 3 个共振峰滤波器（模拟口腔）→ 音高包络。
- "chī"：塞擦音起始（短噪声）+ 高元音 i 的共振峰（F1≈300Hz、F2≈2300Hz）
- "pèng"：爆破音起始（极短爆破）+ 后鼻音 eng（F1≈500Hz、F2≈1000Hz、F3≈2200Hz，带鼻腔共振）
- 调"魔性度"的三个旋钮：音高包络的滑移幅度、共振峰的 Q 值、轻微失谐量
- **诚实说明**：这不是真方言，是**方言味的拟声**（像"鸭子说话"那种卡通感）—— 但那恰恰是最"魔性"的方向

**③ 的做法**：`edge-tts --voice zh-CN-liaoning-XiaobeiNeural --text "吃"` —— 最省事、最像真人，但 **ToS 与方言都对不上**，我不推荐。

> **我的推荐：① + ② 组合。** 先用 ② 做出一版立刻能听、能进包的；同时请你抽 3 分钟录 ①。
> 你的录音到了直接替换文件，**代码零改动**。

### 2.4 「魔性」的具体设计（不论走哪条路径都适用）

| 音效 | 现在 | 改成 | 为什么更魔性 |
|---|---|---|---|
| **碰** | 单次 C-E-G 和弦 | **三连击**：523 → 659 → 784Hz 各一声（间隔 70ms），第三声叠"人声"「碰！」 | 三张牌撞出三声，与"三合一"的视觉对齐；人声尾巴是"魔性"的来源 |
| **吃** | 单条滑音 | **三声「咔嚓」**（与"一口一个"的视觉**逐帧对齐**），末声拖一个上扬尾音（"吃～"） | 有节奏 = 有咀嚼感；尾音上扬 = 满足感 |
| **碰→吃 的分工** | 碰响一声、吃响一声 | 碰**短促重**、吃**连响轻** | 听觉上一听就知道消的是哪种牌型 |

> ⚠️ **音效必须与视觉严格同步**。错开超过 ±40ms，"魔性"立刻变成"乱"。
> 我会在实现时把音效触发点**绑在咬合帧**上（同一处 `setTimeout`），而不是各写各的。

## 3. 问题③：入槽丝滑度与手感

### 3.1 现状时间轴（可从代码推出的实测口径）

```
手指按下  t=0
          ├─ tap 音（节流 45ms）+ 轻震
          └─ 牌缩到 0.96 / 下沉 2px          耗时 TAP_DOWN 60ms
手指抬起
          └─ pickTile：上浮 6px + 放大 1.12   耗时 PICK_SELECT 180ms   ← ★ 原地站 180ms
              ↓
              飞行 flySec = clamp(距离/1.6 px/ms, 180, 300ms)
              ↓
              landTile：换层 + 落位压感 SNAP 140ms
              ↓
              再等 SHIFT_PER_SLOT 90ms 才解锁
          ───────────────────────────────────────────
          输入通道被锁住合计 ≈ 450 ~ 570ms
```

### 3.2 根因（按影响排序）

| # | 根因 | 证据 | 影响 |
|---|---|---|---|
| **1** | ★ **`_busy` 是全局单锁，锁的窗口从"按下"直到"落位后 90ms"** | `pickTile` 设 `_busy=true`（L1377）→ `landTile` 的 `setTimeout` 才清（L1534）；`onTap`/`onTouchStart`/`onPropTap` 全部在开头 `if (this._busy) return` | **"点第二张要等半秒"的主因**；点道具也被卡 |
| **2** | **两段式起飞**：先原地"上浮+放大"180ms，**然后**才飞 | `MotionFx.to2(...PICK_SELECT..., ...flySec...)`（L1398） | 最容易砍的 180ms |
| **3** | 落位后**还多等 90ms** 才解锁 | L1532 `setTimeout(..., SHIFT_PER_SLOT)` | 白等 |
| **4** | 飞行用 `quadOut`（先快后慢）→ **末端减速**"慢慢贴上去" | `EASE.MOVE = 'quadOut'` | 与"被吸进槽"的心理预期相反 |
| **5** | 手感细节偏弱：按下只缩 4%、下沉 2px | `TAP_DOWN_SCALE 0.96` / `TAP_DOWN_DY 2` | "点了像没点到" |
| **6** | ★ **没有输入缓冲**：锁定期的点击被**直接丢弃** | `if (this._busy ...) return` | 快节奏玩家会感觉"我明明点了却不算" |

### 3.3 方案（三档，可自由组合）

#### 档 A —— 保守（只调参数，不动状态机）
- `PICK_SELECT` 0.18 → **0.10**；上浮+放大并进飞行首段（取消独立段）
- `MOVE_MAX` 300 → **240**
- 落位**立即**解锁（`_busy=false` 提到 `landTile` 开头，聚拢动效照跑但不再锁输入）
- 手感：按下缩 **0.94**、下沉 **3px**；`tap` 音前叠一个 **4ms 极短高频 click**（耳机里听得见、外放几乎无感）
- **效果**：单张占用 450~570ms → **≈ 300~360ms（-35%）**
- **风险**：极低（全是参数）

#### 档 B —— 标准（引入**飞行队列**）★ 推荐
在 A 的全部改动上，把 `_busy` 从"单锁"改成**飞行队列**：允许最多 **2 张牌同时在空中**，按**点击顺序**依次落位。

- **效果**：连续点牌不再有等待感，像连珠炮 —— 这才是"丝滑"的正解
- **必须处理的 5 个风险点**（都会在实现时逐个写测试）：
  1. **插入顺序**按点击顺序（不是到达顺序）确定 `insertAt`
  2. **连锁 / 胜负判定**只在**队列排空后**做一次（避免"飞着飞着判负"）
  3. **槽满预占**：队列里待落的牌也算占用（否则第 9 张才判负）
  4. **B7 取消**（点牌撤回）要能取消**队列里任意一张**，不只最后一张
  5. **页面销毁 / 洗牌 / 用道具**：队列必须能**整体作废**（`_busy` 死锁最容易在这里复发）

#### 档 C —— 激进（在 B 上再加"幽灵占位"）
点击瞬间在目标槽位画一个**半透明幽灵牌位** → 玩家立刻看到"这张要去第 3 格"。
用"预告"吸收等待感，心理补偿很大，但对槽位绘制影响面较宽。

> **我的推荐：档 B。**
> 档 A 治标（省约 150ms，但仍会"一下一下"地卡）；档 C 的收益要等 B 做完才测得出来，先不做。

### 3.4 ⚠️ 风险提示（必须一起接受）

`_busy` 是**防死锁**的关键 —— 工程记忆里明确记着"`_busy` 永久为 true = 整局死锁，最严重的一类故障"，
代码里也有多处注释沿着这条线在防（L2713、L2764）。**改它必须配一整套回归验证**：

| 验证项 | 手段 |
|---|---|
| 四关正常通关（含连锁、含吃/碰/杠） | `tools/smoke-run.sh web-desktop ... auto:N` |
| 槽满判负 → 看广告复活 → 环内消除 4 张 | `fill:8` 动作（S11 新增） |

### 7.3 音效候选是怎么来的（可复现）

既然真四川话拿不到（见 §6），本轮的候选走的是**"借真人干声 + 重写声调"**：

- **「吃」**：四川话读 `[tsʰɿ]`，与普通话**「次」cì** 段音完全相同，只差声调
  （普通话去声 51 高降 → 四川阳平 21 低降）。用 edge-tts 合成「次」，再靠 `--pitch` 下移音高。
  → 实测 F0 轮廓落到 `[+1.49, -4.45]` 半音，与目标 21 的 **RMSE = 1.38 半音**。
- **「碰」**：四川话读 `[pʰoŋ]`，普通话**没有 p+ong 这个音节**。借 **「捧」pěng**（上声 214，
  降升形状与四川去声 213 同族），再对整段做 **重采样 ×0.82** ——
  这个操作**同时**解决了两个问题：共振峰按比例下降使韵母 `/ɤ/ → /o/`
  （实测 F2 由 1079Hz 降到 861Hz），时长 +22% 对 0.3s 短音可忽略。
  > 💡 顺带记一条：重采样会等比缩放所有频率，因此**音高轮廓的形状（半音差值）不变** ——
  > 所以 resample 档要按 **F2** 选，不能按轮廓 RMSE 选。

⚠️ 这些是**近似**，不是纯正四川话。正式入库前请换成 §6 表里的真人音源（音效 id 不变，换文件即可）。

### 8.1 音效加长：「延长」是**感知长度**，不是时长数字

**踩到的第一个坑**：在**已经被裁剪过的成品**上加长，尾部的自然衰减早没了，接上去的就是"硬接一截"。
→ 必须**从 raw 原料重建**：`raw_wav()` → resample → `trim2` → 加长。

第二层坑：**`trim()` 的 6% 阈值把真人尾音切掉了**。实测「吃」：6% 阈值下 0.287s、1.2% 下 0.337s
—— 白丢 50ms。→ 新增**非对称裁剪** `trim2(head_th=0.06, tail_th=0.012)`：
头部照旧清干净，**尾部只砍 1.2%**，把真人的渐弱保留下来（那正是"像真人"的来源）。

三层处理（**全时域，不碰谐波**，所以不会引入金属声）：

| 层 | 函数 | 做什么 | 为什么 |
|---|---|---|---|
| ① 非对称裁剪 | `trim2()` | 头 6% 清静音 / 尾 1.2% 保渐弱 | 见上 |
| ② 周期对齐拖长 | `steady_tail()` + `sustain()` | 找**最后一个"还有能量且仍是稳态元音"**的位置，取一个基音周期**重复**，把元音拖长 | 见下面那条最贵的教训 |
| ③ 房间尾音 | `room_tail()` | 合成**指数衰减噪声 IR** → FFT 卷积 → 1.6ms 低通（高频先衰减） | 真人的"尾音"是**空间**给的，不是把元音拉长 |

**★ 本轮最贵的一条教训 —— 周期对齐"从哪取周期"决定成败**
`steady_tail()` 必须同时满足两个判据（能量 + 周期性），并**吸附到声门脉冲峰值**。
只按能量取，会滑进**衰减区**，重复出来的是一段机器嗡声：时长数字变长了，
但听感是 `-62 ~ -68 dBFS` 的近乎静音。**必须逐 50ms 打 dBFS 自检**（见下）。

配套两个修正：
- **自相关窗长必须随音高自适应**（≥4.5 个周期）。固定 30ms 对 74Hz 的男声装不下 3 个周期
  → 自相关 r 假性偏低 → 两个云希候选都"找不到稳态段"。改 `_acf_at` 按粗估周期 ×4.5。
- **`contour_of` 必须加能量门**（`rms_th = 0.18`）。尾部阈值放宽后轻声段的 F0 跟踪不可靠，
  会让调值 RMSE 从 1.38 **假涨到 22**；加了能量门回到 2.1~2.6。
- **`seam_check` 指标是伪值**（同一份代码在 101Hz 与 280Hz 上差 10 倍）→ 废弃，改用
  `period_corr`（周期自相似，0~1，越高越像稳态元音）。死代码 `tail_f0` / `loud_anchor` 一并删除。

### 8.2 手感 v2：延迟的根因不是"飞得慢"，是"原地站着不动"

**根因澄清**（比 §3.2 更准）：`PICK_SELECT = 180ms` 那段"原地站立"里，牌只上浮 6px、
位置几乎不动 —— **人眼把"几乎不动"读成"卡住"**。所以问题不是总时长，是**那 180ms 里没有位移**。

四条改动：

| 改动 | 前 | 后 | 为什么 |
|---|---|---|---|
| `PICK_SELECT` | 0.18s | **0**（当帧起飞） | 见上。`> 0` 的分支**保留在代码里**，调回去就是一键回退 |
| 按下反馈 | `TAP_DOWN_SCALE 0.96`（缩） | **`PRESS_SCALE 1.08`（放）** | 用户要求「点击时可以增加微微放大」；且多层牌堆里"缩小"会被读成"牌变小了、被拿走了"，"放大 + 上抬"只有一个意思——被拈起来了 |
| 按下位移 | `TAP_DOWN_DY +2`（下压） | **`PRESS_DY -3`（上抬）** | 与放大一起构成"拈起来" |
| 飞行 | `MOVE_SPEED 1.6` / `MIN 180` / `MAX 300` / `quadOut` | **2.8 / 90 / 140 / `EASE_FLY`(quadIn)** | 「加快速度飞入槽位」+ 末段减速会读成"小心翼翼地贴上去" |
| 落位解锁 | 落位后仍等 `SHIFT_PER_SLOT(90ms)` | **落位当帧解锁** | 「能不能点下一张」与「槽位排好序」是两件事，已解耦（判定仍延后） |

- ★ **`EASE_FLY` 必须与 `EASE_MOVE` 分开**：后者是 `quadOut`，被"槽位聚拢 / 洗牌铺开 / HUD 下落"共用
  —— 那些场景**就该**减速收尾。改 `EASE_MOVE` 会连带改坏它们。
- ★ **输入缓冲只缓"最后一次"**（一个字段 `_buffered`）：天然无并发、无队列。
  真正的飞行队列有 5 个风险点（插入顺序 / 判定等排空 / 槽满预占 / B7 撤队列任意一张 / 道具洗牌整体作废），
  **本轮不做**（那是 §3.3 的 B 档）。
  - ⚠️ **补做前必须重新校验**（`_taken` / `_blocked`），否则会凭空多占一格、严重时误判"槽满"判负。
  - ⚠️ 缓冲是**局内状态**：`finish()` / 复活 / `onLeave()` 三处都必须清零，否则会跨局执行。
  - ⚠️ 被压住的牌**不进缓冲**（那是"点错了"，不是"丢掉的点击"；补做等于把错误手势执行一遍）。

### 9.3 ⚠️ 顺带修掉 `spawnJaw` 的两个 bug（都是"看不出来"的那种）

这两个 bug 是 S12 存进补丁时带进来的，**编译不报错、运行不报错**，只是"看起来不像嘴"：

| # | bug | 后果 | 修法 |
|---|---|---|---|
| 1 | **弧的拱向写反了**：注释写"上颚向上拱"，代码却是 `quadraticCurveTo(0, -bow, ...)`（= 向下拱） | 两条弧**穿过中线互相交叉**，画面上是个 **"X"** | 控制点符号改成**朝外**（上颚 `+bow`、下颚 `-bow`） |
| 2 | **`bow` 默认值 10**（demo 里用的是 **34**） | 弧被拉成近乎直线，像两根横杠 | 落到 `CFG.MOTION.EAT_MOUTH_BOW = 34` |

### 9.4 「一个嘴咬 N 次」—— 三口重叠的几何问题

三口在时间上**重叠**（`EAT_SUCK` 0.20s > `EAT_STAGGER` 0.13s）。
若每口各起一个嘴，会有两个**同位置、同线宽、只有高度不同**的弧叠在一起 ——
看上去像"上下颚各长出两条"的重影。demo 的 canvas 版用 `max()` 合并成一条曲线绕开了它，
那是逐帧重绘的做法，tween 驱动做不到。

→ 给 `spawnJaw` 加 `bites` / `reopenDur`，链的形状变成：

```
张开(openDur) → [咬合(biteDur) → 再张开(reopenDur)]×(bites-1) → 咬合 → 停留
```

**只要 `reopenDur = EAT_STAGGER − EAT_MOUTH_BITE`，每次"合拢的开始"就精确落在该口"牌到位"的时刻**：

| 事件 | 时刻 | 与谁对齐 |
|---|---|---|
| 第 1 / 2 / 3 张起步 | 0 / 0.13 / 0.26s | `EAT_STAGGER` |
| 第 1 / 2 / 3 次合拢开始 | 0.20 / 0.33 / 0.46s | 各张**到位**时刻 ✓ |
| 打嗝 | 0.68s | 最后一口咬完 + `EAT_BURP_DELAY` |
| 数据收尾 | 0.94s | 打嗝视觉结束 |

### 9.5 唇的透明度改成"跟着开合走"

合拢时两弧贴合，形状是一条"眼睛形的细缝"（demo 原话："看着像渲染 bug"）。
demo 用 `open < 4 就不画` 绕开；tween 驱动做不到逐帧判断路径，
改成**透明度与位置共用同一张 `parts` 表**：张开 → 可见，合拢 → 淡尽。

- 张开段用 `EASE.ENTER`(quadOut，前快) → 唇很快清晰、"张嘴"看得见；
- 合拢段用 `EASE.EXIT`(quadIn，前慢后快) → 唇大部分时间还实着，最后一下才淡掉。

连带删掉 `spawnJaw` 的 `fadeDur` 参数与 `CFG.MOTION.EAT_MOUTH_FADE`
（唇在最后一次咬合时已淡尽，再配一个"淡出时长"是**永远不起作用**的参数）。
